About Acter

Acter help

Three short sections about what you hear when you run a command. Use your reader's heading key to move between them.

What you always hear

When you run a command, Acter reads out what the command prints. It also keeps it in the results area above the command line, so you can go back over it with the arrow keys, or jump between commands with your reader's heading key.

What you sometimes do not hear

Acter cannot see whether a command worked. It has to be told, by the shell it is talking to. Some shells are set up to tell it and some are not.

When the shell tells Acter, you hear a short sentence at the end of a command that failed, such as "command failed, exit code 3", and you hear nothing extra when it worked. That is the only difference. You are not missing any of the output either way.

When the shell does not tell Acter, you can still see how a command went from what it printed, which is what you would do at any other terminal.

Which sessions are which

Sessions on this computer — Command Prompt, PowerShell and WSL — set themselves up when they start, so they normally tell Acter how commands end.

A session on another computer, reached over SSH, normally does not. Setting it up means changing something on that other computer, which Acter will not do without asking you first.
