# Spec: PR A5.2 — announcement serialization in the announcer

## Why now

A5.2 is the next lane-1 entry in `ROADMAP.md`. It fixes a defect found in A3.1's NVDA
run (recorded there and sharpened in `docs/DESIGN.md`'s announcement-channel open
question): two `CommandInterrupted` events for two concurrently-stopped scripted
commands arrive as **two separate messages**, the controller calls `announce()` for
each, and both land in the live region in **one mutation** — which NVDA reads as one
concatenated utterance, "command stopped command stopped". The mechanism is general (an
auto-read chunk immediately followed by a failure would merge the same way), so the fix
belongs in the announcer: the only layer that owns when the live region mutates.

The roadmap also assigns this entry the **render-before-announce invariant**: text must
never be announced before it is in the buffer. Today the buffer is mutated synchronously
inside the channel handler, so the controller's existing order (render, then call
`announce`) already satisfies it. This spec pins that order with a test rather than
adding machinery for async rendering that does not exist yet.

## Design decisions this spec makes

1. **The announcer becomes a queue drained one announcement per turn.** `announce(text)`
   no longer touches the DOM; it enqueues. A drain loop mutates the live region at most
   once per turn, so no two announcements ever share a live-region mutation batch. The
   single polite region, the "never recreate the region node" rule, and the
   clear-after-idle behavior (now restarted per drained item) are unchanged.

2. **The separation mechanism is measurement-driven, not assumed.** The captured
   evidence proves "one mutation → one utterance"; it does not say whether separation
   requires a *gap* between mutations or a *boundary token* inside them. The default is
   temporal — drain one item per turn. If the bridge shows merges persist, the fallback
   is structural — insert a `<br>` separator between successive announcements. The
   implementing PR measures which mechanism (or which combination) NVDA actually needs
   and lands that one.

   **Measured (NVDA 2026.1.1, WebView2, silent capture, two commands stopped at once):**
   a distinct macrotask is necessary but *not* sufficient — WebView2 batches
   accessibility updates per rendering lifecycle, so mutations inside one batch still
   reach NVDA as a single live-region change. At 1 ms, 50 ms, and 75 ms the two stops
   merged into one `command stopped command stopped` utterance; at 100 ms and 250 ms they
   were captured as two separate utterances. The threshold on the test machine lies
   between 75 ms and 100 ms, so 100 ms is the edge rather than a safe setting: the landed
   value is **250 ms**, roughly 2.5x the measured threshold, to absorb machine load,
   WebView2 version, and NVDA cadence. A temporal gap alone was sufficient, so the
   structural `<br>` fallback is **not** used.

   **The gap is between announcements, never before one.** A first cut applied the
   spacing as a flat delay on every drain, which taxed the common case — a lone
   announcement — 250 ms for a merge that could not happen, since there was nothing to
   merge with. The drain now waits only for the remainder of the gap since the *last*
   drain, so an announcement arriving into an idle region is as prompt as it was before
   serialization and only the second and later items of a burst pay. Re-measured on the
   bridge: two stops still separate (254 ms apart), and `fail` still separates (201 ms
   apart).

3. **No coalescing and no new strings.** Two stops are spoken as two `command stopped`
   utterances. `command stopped` and every other pinned string stay byte-identical and
   single-sourced in `controllers/app.ts`.

4. **Render-before-announce is guaranteed by deferred drain plus the controller's
   existing order.** Because `announce` only enqueues and the live-region mutation
   happens on a later turn, it can never precede the synchronous buffer append that ran
   before `announce` was called. The convention is pinned by a controller ordering test;
   a `commit()`/acknowledge gate is **explicitly deferred** to the future PR that makes
   buffer rendering asynchronous (`requestAnimationFrame` batching). That PR must add
   the gate then — recorded in DESIGN's open question so it is not forgotten.

5. **The live region stays a single polite region.** Separate-region, polite-vs-
   assertive, and cross-region ordering remain the DESIGN.md open question, untouched.

## Deliverables

- `ui/src/adapters/announcer.ts` — enqueue on `announce`; drain at most one item per
  turn (named, tune-able spacing constant, landed at `250 ms` per the measurement in
  decision 2 — the gap must clear WebView2's accessibility batching window, not merely
  the JS task queue); structural-separator fallback not needed and not applied; clear
  timer and region-node lifecycle preserved.
- `ui/src/ports/announcer_view.ts` — doc comment updated to state the queue/drain
  contract. **No signature change**: `announce(text: string): void` stays.
- `ui/src/controllers/app.ts` — no behavioral change; a comment establishes the
  render-then-announce order as the pinned invariant. No pinned strings change.
- Tests (vitest):
  - `ui/test/adapters/announcer.test.ts` (jsdom, fake timers): two back-to-back
    `announce` calls do **not** produce both nodes in one drain turn; they appear in
    separate turns in order; the clear timer restarts per drained item and empties the
    region after idle; the region node is never recreated.
  - `ui/test/controllers/app.test.ts`: an auto-read `Output` records the buffer append
    **before** the announce call, pinning render-before-announce.
  - The existing A3.1 stop test and the announcer lifecycle tests keep passing unchanged.
- Docs:
  - `docs/DESIGN.md`: close out the announcement-channel open question's A5.2 portion —
    the announcer now serializes announcements (queue, one per turn, separator fallback);
    separate-region, polite-vs-assertive, cross-region order, and the future async-buffer
    commit gate remain open/noted.
  - `docs/ROADMAP.md`: in the implementing PR, flip entry 9 (A5.2) to Done with this
    spec's path.

## Acceptance criteria

1. `npm run typecheck` and `npm run test:ui` green.
2. Two `CommandInterrupted` announcements for two stopped commands reach the live region
   in **separate drains**, and speak as two distinct `command stopped` utterances —
   never "command stopped command stopped".
3. Two *distinct* announcements in the same tick (e.g. error output then "command
   failed, exit code 2") are preserved in order as separate announcements, never merged
   and never clobbered.
4. Render-before-announce is asserted by test: an auto-read `Output`'s buffer append
   precedes its announce call.
5. The region is emptied after the idle window and remains the same DOM node throughout.
6. Every pinned string appears verbatim in exactly one place in the frontend; no new
   strings are introduced.
7. Manual NVDA checklist below completed in the PR body; the separation mechanism is
   measured through the screen-reader bridge and the chosen mechanism (gap and/or
   `<br>`) recorded with its evidence.

## Manual accessibility checklist (PR body)

One checkbox per item; findings written inline on the unchecked item (NVDA version,
expected vs observed):

- Two scripted commands running, then `stop`: two `command stopped` utterances are heard
  as separate, distinguishable announcements. Record verbatim and count.
- `fail`: the error output and "command failed, exit code 2" are heard as two separate
  announcements.
- `big`: the "too big" announcement is complete and not merged with the following
  beep-finish state.
- Bridge measurement: the drain spacing (and, if needed, separator) at which two
  additions are captured as separate utterances; a human check records whether separate
  captures are *perceptibly* separate by ear.

## Out of scope

- Separate live regions, polite-vs-assertive, cross-region ordering — remain the open
  DESIGN question.
- `requestAnimationFrame` buffer batching and the `commit()` gate — deferred to whichever
  PR introduces async rendering, recorded in DESIGN.
- Coalescing/counting announcements into a single summary — rejected (decision 3).
- Backend pacing changes, Ctrl+C (A3.2), completion (A4), boundary (B2).
