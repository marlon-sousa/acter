# V2.3 — the far end's row is drawn once

Lane 5, the look; roadmap entry 53.3.

## What is true today

Measured on 2026-09-23 against PowerShell in far-end line mode, over the embedded WebDriver:

- **`gh repo create`'s selection list.** After one Down arrow, the buffer showed the list with
  `> Create a new repository on github.com from a template repository` as its second option,
  and the far-end field held the same text, so it appeared again as the last line on screen.
- **After Ctrl+C cancelled `gh`,** the buffer ended with the prompt `PS C:\Users\marlo>` and an
  empty output block, and the far-end field held `PS C:\Users\marlo>` too, with the caret drawn
  at its start. It stayed that way until the next key.
- With `Read-Host`, a choice prompt and idle prompts, the field held only what was typed, and
  nothing was drawn twice.

Read from the code on 2026-09-23 (spec 28 and `session.rs`):

- The field shows whatever `SessionEvent::FarEndLine { text, caret }` carries. Its only producer
  is `Pump::far_end_line`.
- After a key, `far_end_row` (`far_end_row.rs`) answers in the order spec 28 decision 6 lays
  down:
  - step 1: the anchored row changed, so the answer is the text from the anchor column;
  - step 2: some changed row gained content, so the answer is **that whole row from column 0,
    with caret 0**;
  - step 3: only the caret moved.
- Step 2 exists for `gh`, which hides its cursor and never changes the anchored row.
- Every row the region filter admits also reaches the buffer: `on_anchor` decides speech only,
  pinned by the test `the_anchored_row_is_rendered_and_never_spoken`. A step 2 row is therefore
  both in the buffer and in the field. That is the `gh` duplicate.
- In far-end mode, Ctrl+C is a key: byte `0x03` through `far_end_key`, pinned by the test
  `ctrl_c_reaches_the_far_end_as_a_byte_rather_than_an_interrupt`. It does not clear the anchor
  as Enter does (`far_end_submitted`: `anchor = None`, `awaiting_prompt = true`).
- After `gh` exits, `follow_cursor` cannot move the anchor, because the held text is not a suffix
  of the new prompt row. The new prompt row "gained content", so step 2 puts it in the field
  whole, with caret 0. Nothing re-anchors until another read arrives, because a far end sitting
  at its prompt sends nothing more.

## Decisions

1. **Ctrl+C sent to the far end prepares for a new prompt, as Enter does.** When the bytes of a
   far-end key are `0x03`, the pump clears the anchor and sets `awaiting_prompt`, exactly as
   `far_end_submitted` does. The next settling then takes the anchor at the cursor, so the field
   holds only what follows the prompt. If the program stays and keeps its cursor visible, that
   settling anchors wherever the cursor is, which is what happens after Enter today.
2. **The field says when its text is not the command line.** `FarEndLine` gains `anchored: bool`:
   true for step 1 and step 3, and for `anchor_here`; false for a step 2 row. The text and caret
   stay exactly as today, so NVDA hears the same thing.
3. **A step 2 row is drawn once.** When `anchored` is false, the frontend gives the field the
   class `detached`, and CSS draws its text and caret transparent. The text stays in the field,
   so NVDA reads it as today. The same row is on screen in the buffer, where the far end drew it
   with its `>` marker. The class goes away with the next anchored `FarEndLine`.

## What V2.3 does not do

- It does not stop step 2 rows reaching the buffer. Spec 28 decision 8 keeps the far end's own
  record, and that record is what a sighted person should see.
- It does not change what is spoken.

## Acceptance criteria

1. Session tests:
   - Ctrl+C in far-end mode clears the anchor and sets `awaiting_prompt`;
   - the settling after it anchors at the cursor, and the field's text is empty;
   - the step 2 widget test (`a_widget_that_hides_its_cursor_still_gets_the_content_rule`) now
     expects `anchored: false`;
   - step 1 and step 3 expect `anchored: true`.
2. Far-end field tests: `detached` follows `anchored`; text and caret rendering are unchanged.
3. All existing tests pass, with helpers gaining the new field.
4. Against PowerShell in far-end mode, screenshots show `gh repo create`'s list with the
   selected option once, and, after Ctrl+C, the prompt once with the cursor after it.
5. NVDA 2026.1.1 through the bridge, `user` persona: arrowing `gh`'s list speaks the selected
   option as today, and after Ctrl+C the command line reads empty, not as the prompt.
