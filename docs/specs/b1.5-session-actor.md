# Spec: PR B1.5 — session actor and the `Clock` port

Agreed in conversation 2026-08-16. Lane 2, entry B1.5, placed ahead of B2 by decision.
Delivers the first caller of the B1 pacing policy: one session's actor loop, the
`Clock` port it waits on, and the mapping from pacing decisions onto protocol events.

## Why now / relation to the roadmap

- B1 shipped a pacing policy with no caller, so its entire scheduling contract is a
  hypothesis no code has exercised. `wake_after` has never been armed on a real timer.
- B1.1 deepened that: its empty-chunk rule restates a pending deadline rather than
  returning `None`, specifically so a caller re-arming on every outcome cannot drop a
  flush it was already waiting for. Nothing makes that choice real.
- DESIGN's "buffer and speech are separate paths" rule needs a first implementer; the
  actor is the layer the rule is actually about.
- B2 is independent of all of this and can wait. Proving the timer loop cannot.

## Design decisions this spec makes

1. **The actor is a controller, not a service.** ARCHITECTURE's litmus test: deleting it
   loses connectivity, not business behavior. It coordinates the policy, the entities and
   the ports for one session, holds the runtime machinery (a tokio task, channels,
   timers), and stays framework-free. Lives at `controllers/session_actor.rs` in
   `acter-core`, where the reference layout already places it.
2. **`acter-core` takes `tokio`, with `sync` and `macros` only — no `rt`.** That core
   gains tokio is not a deviation: ARCHITECTURE already places `controllers/` in this
   crate, says controllers "own runtime machinery (async tasks, channels)", reserves
   async for the orchestration layer "(tokio — Tauri brings it)", and decides that each
   session is one tokio task. Core is meant to carry no *adapters* — those live in
   `acter-transports`, `acter-shells`, `acter-term` and `acter-app` — which is a
   different constraint from carrying no dependencies. "Sync pure core" governs entities
   and policies, which stay synchronous state machines, not the crate's dependency list.

   The decision worth making is which tokio. Core needs the primitives, not the runtime:
   channels and `select!`, with the `rt` feature deliberately absent, so core
   *structurally cannot* spawn a task or build a runtime. The actor exposes `run()` as a
   future and the composition root spawns it. "One runtime, owned at the top" then holds
   by the dependency graph rather than by convention.
3. **`Clock` reports monotonic elapsed time as a `Duration`, and hands out timers.**
   `now()` returns a `Duration` since the clock's own origin, never an `Instant`, so B1
   decision 3 survives intact — no handle on the real clock crosses into the domain, and
   elapsed-since-command-start is one subtraction of two values from the same origin. The
   adapter keeps the `Instant` internally. Waiting is `timer(after) -> TimerHandle`, a
   receiver the actor selects on, rather than a `sleep` the actor blocks inside: a fake
   clock then records what durations were requested and fires them on command, so tests
   drive time by hand with no tokio time machinery and no real waiting.
4. **The actor's inputs are domain facts, not bytes.** An input channel carrying
   "text arrived", "command started", "command ended with this exit code", and "follow
   mode changed". Extraction, OSC 133 recognition and PTY reading are B2/B3/B4's; they
   later become the things that feed this channel instead of a test. The actor therefore
   needs no `Transport`, no `TerminalEngine` and no boundary tracker to exist.
5. **Two paths, two cadences (DESIGN, Decided).** Rendering is unconditional and runs on
   a short coalescing tick; speech runs on the pacing windows and is the only path the
   policy governs. Going quiet never withholds text.
6. **The actor stores unspoken text only while it could still be spoken.** Once the
   unspoken span passes the auto-read threshold its verdict is already settled as
   `TooBig`, and a too-big announcement needs only the line count — the text itself is
   already rendered and reviewable. So beyond the threshold the actor keeps counts and
   drops the bytes. Memory is bounded by `max_chars`/`max_lines` no matter how fast
   output arrives, which is what finally closes the gapless-flood case (`yes`, a busy
   `tail -f`) that no pacing rule reaches: under a flood no quiescent gap ever occurs, so
   nothing would otherwise ever be flushed or freed.
7. **Render before announce, carried by emission order alone.** The actor emits the
   rendering event covering a span before any announcement about it. Nothing correlates
   the two: the per-session Channel delivers in order (ARCHITECTURE chose Channels for
   "ordered, caller-bound delivery") and the frontend handles events in arrival order, so
   by the time an announcement is handled its text has already been appended. No ids, no
   lookups, no waiting on a referenced event that might never arrive. DESIGN's invariant —
   never announce text that is not already in the buffer — is therefore enforced by
   sequence, and asserted against a recorded event stream rather than assumed.

   Arrival order is not by itself enough, and the gap is the frontend's: a buffer that
   batches DOM appends into a `requestAnimationFrame` while the announcer speaks on
   receipt would invert the order with no test noticing. So the rule — **rendering is
   immediate, announcements may be delayed, never the reverse** — must be *enforced*
   there, not merely documented. The mechanism, owned by A5.2 and specified in its entry:
   the announcer never speaks on receipt; it enqueues, stamping each arrival with a
   monotonic index, and drains only entries whose index the buffer has already committed.
   A batched render delays an announcement by one commit, which is one frame; under a
   flood, the only case where rendering could fall meaningfully behind, the babble guard
   has already silenced announcements, so the pathological tail does not exist.

   **Why the watermark is not in the protocol.** An explicit "not before output N" field
   on the announcement was considered and deliberately left out: while everything travels
   on the single ordered per-session channel, the frontend's arrival index *is* that
   watermark, and shipping a number the receiver can already derive adds a second source
   of truth that can drift from the first. It stops being derivable the moment
   announcements travel separately from output — which is precisely what DESIGN's open
   announcement-channel question may decide. Recorded here with its trigger: if
   announcements ever leave the output channel, the not-before field becomes required in
   the same change.
8. **One event per fact; the actor never rate-limits announcements.** Two announcements
   that are true at the same moment travel as two distinct, individually identified
   events. A3.1's merged utterance was not an upstream ambiguity — two distinct
   `CommandInterrupted` messages arrived separately and the announcer appended both into
   one node in one tick — and the announcer owns the pinned strings, so it is also the
   only layer that can coalesce them into a counted form. Utterance separation is A5.2's;
   this entry must only avoid making it worse.
9. **Speaking is its own event, and it is self-contained.** Rendering and announcing
   travel as two distinct events even when they describe the same text, rather than one
   event whose flag decides whether it is also spoken. As long as a single event type can
   mean both, the two paths stay coupled in the type system and DESIGN's separation
   survives only by everyone remembering it. Split, the frontend stops branching —
   `Output` appends to the buffer, an announcement goes to the announcer — which is
   exactly the single entry point A5.2's queue needs, and it lets the two cadences be
   tuned independently, which was the point of separating them.

   The duplicated text is close to free, for the reason the size threshold already gives:
   an announcement only carries text when the text is small enough to read aloud. Over
   the threshold it carries a line count instead, and under a flood the babble guard
   silences it entirely — so duplication is bounded by `max_chars` at roughly two per
   second, against a render stream that may be megabytes per second. The alternative,
   an announcement addressing a span of already-rendered output, collides with the decided
   frontend line cap: a span can be evicted before speech resolves it, and a reader that
   goes silent when it was told to speak is the worst failure available here.

   The payload is therefore not "text" but a small enum, because only auto-read carries
   text at all and the frontend owns every string:
   `Announce { command_id, announcement }` where the announcement is read-aloud with
   text, too-big with a line count, still-running, output-continues, or failed with an
   exit code. That also unifies things scattered across the protocol today —
   `CommandStillRunning` is its own variant, failure rides `CommandFinished.exit_code`,
   too-big rides `Output.read_mode` — into one kind the announcer can queue uniformly.
10. **The protocol change is additive, and the cleanup is A6.** B1.5 adds `Announce` and
    the actor uses it exclusively, emitting rendering events that carry no verdict.
    `Output.read_mode`, `CommandStillRunning`, and the failure-via-`CommandFinished` path
    all stay in place, unused by the actor, because A2's exhaustiveness guard fails `tsc`
    until the frontend handles every variant — so a protocol addition cannot be split
    across two PRs, while a removal can wait. The cost, named rather than discovered in
    review: for one PR cycle the frontend has two ways to be told to speak, since the A3
    fake keeps emitting the old shape while the actor emits the new one. A6 retires the
    old shape and migrates the fake.
11. **Patience keeps its per-command latch.** Left exactly as B1 specced it, to be
    revisited against NVDA evidence once pacing is audible rather than guessed at twice.

## Deliverables

### `ports/driven/clock.rs`

- `Clock` (role: port, driven): `now() -> Duration`, monotonic from the clock's origin,
  and `timer(after: Duration) -> TimerHandle` for waiting. Documented invariant: `now()`
  never decreases.

### `controllers/session_actor.rs`

- `SessionActor` (role: controller) owning one session's `PacingState`, `SessionState`,
  render buffer and unspoken accumulator, holding `Arc<dyn Clock>` and `Arc<dyn
  EventSink>`.
- The loop: select over the input channel, the render tick and the pacing timer; call the
  policy; emit events; re-arm.
- Per-command lifecycle: a fresh `PacingState` at command start, retired at command end.

### Protocol

- `Announcement` (role: entity/value): read-aloud with text, too-big with a line count,
  still-running, output-continues, failed with an exit code. The last two close B1
  decision 7's recorded hole — the babble announcement has had no protocol variant since
  B1.
- `SessionEvent::Announce { command_id, announcement }`.
- Regenerated `ui/src/protocol.ts`, and the minimal frontend handling A2's exhaustiveness
  guard requires: `Announce` reaches the existing announcer, with the pinned strings it
  already owns. Deliberately minimal — the announcer rework is A5.2's and the retirement
  of the superseded shapes is A6's.

### Tests

No Tauri, no real time, no sleeping. A fake clock records requested durations and fires
them; a recording `EventSink` captures the stream.

- **The scheduling contract:** a wake is armed for exactly the `wake_after` the policy
  returned; an empty chunk mid-window does not move the deadline out (B1.1's rule, tested
  from the caller's side for the first time); a chunk arriving inside the window extends
  it.
- **Both paths:** rendering happens on the tick regardless of every pacing verdict;
  a tripped babble guard keeps rendering and stops announcing.
- **The invariant:** for every `Announce` in a recorded stream, the rendering event
  covering its text appears strictly earlier. Asserted over whole streams, not per call,
  because sequence is the whole mechanism.
- **Bounded memory:** a flood with no quiescent gap never grows the unspoken accumulator
  past the threshold, and still announces the right line count.
- **Lifecycle:** a second command starts from a fresh `PacingState`; patience and the
  babble guard do not leak across commands.

## Acceptance criteria

1. `cargo test --workspace` green.
2. No test sleeps, and no test reads the real clock.
3. The actor is reachable only through its input channel and its ports; nothing in
   `acter-core` outside `controllers/` names `tokio`, and `acter-core` does not enable
   tokio's `rt` feature — the crate cannot spawn a task or build a runtime.
4. Module role declared on the first line of each new module's `//!` comment; the
   visibility ladder holds.
5. Protocol drift guard green (regenerated, if the variant lands here).

## Out of scope

- Session manager, tabs, `get_session_snapshot`.
- OSC 133 recognition and the boundary tracker (B2) — the actor is *told* a command
  started, it never recognizes a marker.
- Any wiring of the actor into `acter-app`: the A3 fake stays the default backend until
  convergence, so this PR adds no user-facing behavior and carries no accessibility
  checklist. The frontend change it does make is the minimum A2's exhaustiveness guard
  demands, against strings already NVDA-validated in A3 and A3.1.
- Utterance separation — A5.2, which can land before or after this and depends on
  neither.
- Retiring `Output.read_mode`, `CommandStillRunning` and failure-via-`CommandFinished`,
  and migrating the A3 fake onto `Announce` — **A6**, which strictly depends on this
  entry. Decision 10 explains why the removal cannot ride along with the addition.

## Implementation notes (amendments, added during implementation)

- **The actor's decision logic is synchronous methods; `run` is a thin loop over them.**
  `handle`, `wake_render` and `wake_pacing` mutate state and record what they want done
  with each timer in a `Requests { render, pacing }` of `Wake::{Unchanged, Clear,
  After}`; `run` selects over the inputs and the two timers, calls one method, and
  applies the requests. Tests then drive the methods directly and read the requests back,
  so "a wake was armed for exactly the `wake_after` the policy returned" is asserted as a
  value rather than inferred from timing. Only one test needs a runtime at all, and it
  exists to prove the loop wires the pieces together.
- **`entities/unspoken_text.rs` is a new entity module**, not in the deliverables list.
  Decision 6's bound is a real invariant over data — text held only while it could still
  be spoken, line counts exact either way — so it is an entity with its own tests rather
  than private bookkeeping inside the controller. Its `Default` is hand-written: `None`
  means "bytes deliberately dropped", so an empty accumulator must hold an empty string,
  and deriving `Default` silently made every span look already-overflowed.
- **`PacingConfig` gains `render_tick` (50ms).** The rendering cadence is ARCHITECTURE's
  number ("a short tick (tens of ms)"), not DESIGN's, and it governs the path no policy
  decides. It lives in `PacingConfig` anyway because that is where pacing numbers live,
  documented with its different provenance so B1's "every DESIGN-decided number appears
  exactly once" is not read as claiming this one is DESIGN's.
- **No production `Clock` adapter yet.** The port has a consumer (the actor) and an
  implementer (the test clock), which is what shapes a port; a real one wrapping
  `Instant` is a dozen lines but nothing would construct it, and an unconstructed adapter
  fails CI under `-D warnings`. It lands with the wiring that first spawns an actor.
