# Spec: PR B6.1 — correlation that cannot drift

Agreed in conversation 2026-08-21. Lane 2, entry B6.1. An iteration entry from B6's
manual NVDA pass, not a planned step: it closes the one hole B6's decision 3 accepted
knowingly, using evidence the tracker already produces and the pump already sees.

## Why now / relation to the roadmap

B6 minted a `CommandId` at submission and claimed it at `BlockStarted`, and accepted
one edge without a rule: a submission that never opens a block leaves its id queued,
and the next block claims it. The manual pass showed the consequence is worse than
"one command may be mis-attributed". The queue never recovers, so from the first drift
onward **every** block carries the previous command's heading and every answer is heard
under the question before it. B6's spec records that amendment rather than softening it,
and names two candidate fixes for this entry to choose between.

What makes the fix reachable now is that nothing new has to be observed. The tracker
already labels the B..C region as `Region::CommandLine` — that is the shell saying which
line it read — and `AlacrittyEngine::advance` extracts text *before* it places each
marker, so the echo of a submitted line arrives at the pump as `BoundaryEvent::Line` with
that region strictly before the `BlockStarted` that follows it. The pump throws it away
today (`wants` excludes it, which is DESIGN's echo exclusion and stays true of *output*).

The trigger that surfaced this manually — the built-in transcript's `stop` rule minting
an id for what is a keystroke in the shipped product — is gone since A3.2. The hole is
not. Two triggers remain reachable against a real shell, and neither involves a fake:
a line typed into a full-screen program while the alternate screen is up, and a line the
shell reads but does not run, which is what an unterminated quote does when PowerShell
answers with a continuation prompt.

## Design decisions this spec makes

1. **The heading is what the shell echoed, not what the frontend guessed.**

   `SessionEvent::CommandStarted` gains `command_line: Option<String>`: the text of the
   B..C region for the block that just opened, when the pump could read one. The frontend
   prefers it over the optimistic text it put on the block at submission time.

   The optimistic heading stays, and must: it is what makes the block appear the instant
   Enter is pressed, which is the round trip ARCHITECTURE asks for and the only thing a
   listener has to hold on to while a command runs. What changes is that it is no longer
   the *last* word. An id that drifts can then still route output to the wrong block; what
   it can no longer do is put the wrong words on it.

   **`Option` and not `String`, deliberately**, against A6 decision 6's caution about
   weakening a type to fit one case. Absence here is a real domain state and not a
   missing value: a session with no shell integration has no B..C region at all, a shell
   may emit `C` with no echo before it, and a rewritten echo whose prompt prefix cannot
   be identified (decision 2) is deliberately reported as unknown. `None` means "the shell
   did not tell us", and the frontend's answer to that — keep the heading you have — is
   the honest one. A `String` that is sometimes empty would say the same thing less
   clearly.

2. **Reading the echo: appends accumulate, a rewrite must prove itself, anything else
   is unknown.**

   The extractor emits a live line's *delta* as `LineRevision::Appended`, so the echo of a
   submitted line arrives as exactly the text the shell echoed, with the prompt it was
   written after already excluded. Those deltas accumulate.

   A `Rewritten` item carries the whole row, prompt included — the row the prompt was
   drawn on is the row the echo is written onto, which is why `AlacrittyEngine::place`
   refuses to settle a block's lines at `A` or `B`. So the pump keeps what the prompt
   region put on the current row and strips it as a prefix. If it does not match, the echo
   is marked **unknown** and the event carries `None`: a heading that might contain the
   prompt is worse than no correction, and this is the case a real PSReadLine redraw will
   exercise first when B5 lands.

   The accumulator resets on any line outside `Region::CommandLine`, which is what
   separates one command's echo from the next: between two commands the tracker reports
   `Output`, then `Unstructured`, then `Prompt`. Two consecutive command-line rows with
   no prompt between them accumulate together, which is the right answer for a
   continuation line — the block's command line genuinely is both rows.

   Text in `Region::CommandLine` is still never block content. This decision reads the
   echo; it does not forward it as output.

3. **A matching echo retires the ids the shell skipped.**

   The pump keeps each queued id's submitted text beside it. At `BlockStarted`, when the
   echo is known and does not match the front of the queue but does match a later entry,
   the entries in between are retired and that later id is claimed.

   This is the rule B6 said no marker could supply, and it is not the rule B6 forbade.
   The forbidden one — retire the queue at the next prompt — infers from a marker's
   *absence* that a line will never run, and a real shell draws its prompt before it reads
   a line a fast typist already sent, which is why
   `blocks_claim_submitted_ids_in_the_order_they_were_submitted` exists. This one infers
   from *positive evidence*: the shell has said, in its own echo, which line it is running
   now. Phase 1's shell is serial and reads lines in the order they were written, so a
   shell running a later submission has already disposed of the earlier ones as something
   other than command lines — into a full-screen program, into a continuation, into a
   password prompt. They are not pending; they are over.

   Matching is **exact after trimming**, never fuzzy. Trimming is normalization, not
   guessing: a shell's echo of a line may carry the trailing spaces the row was padded
   with. Anything less certain — a prefix match, a similarity score — would be the guess
   decision 3 refused, so a non-match simply falls back to B6's FIFO claim with the
   heading of decision 1 on top. Two identical submissions match at the front and nothing
   is skipped, which is correct: the shell is running the older one.

   The rule also unsticks a fact B6 could not: `settle_running` counts queued ids, so a
   drifted session today reports "something is running" forever and `Ctrl+C` can never
   answer `nothing running to stop`. Retiring the skipped ids restores that answer.

4. **A retired id's block is left standing, and nothing is announced about it.**

   The frontend has a block for a retired id, with the heading the user typed and no
   output. It stays that way: the user did type that line, and it did produce nothing, so
   an empty block is what happened. Buffer focus lands on the newest heading, which after
   a retirement is the block that is actually running, so the case that made this audible
   is closed.

   Saying more would need a new event meaning "this never ran" plus a pinned string for
   it, and neither the alternate-screen case (the line went into `nano`) nor the
   continuation case (the shell is still reading) is a *failure* worth interrupting a
   listener for. If the standing blocks turn out to matter in use, that is a wording
   decision to make in the open with a listener present, not a side effect of this one.

5. **The alternate-screen rule is not needed and is not added.**

   The roadmap's second candidate — retire ids minted while the alternate screen was up —
   is subsumed by decision 3 for every session that echoes: the next real command's echo
   retires them, whatever consumed them. Adding it as well would be a second rule with a
   narrower justification and a race of its own (a line submitted in the moment between a
   program exiting and the pump reading `AltScreenLeft` would be retired although it is a
   real command line). One rule, resting on evidence, is the smaller thing to defend.

   A shell that does not echo at all keeps B6's behavior exactly, which is the fallback
   this entry deliberately does not try to improve on.

## Tests

Service-level, in `services/session.rs`:

- A block's `CommandStarted` carries the echo the shell wrote between `B` and `C`.
- An echo that arrives as several appends is one command line.
- A rewritten echo whose prompt prefix is known is stripped to the command line; one
  whose prefix does not match reports `None`.
- A session with no echo at all still opens the block, with `None`.
- **The drift test**: a submission that never opens a block, then a second submission
  whose echo matches it, claims the second id — and the first is not claimed by any later
  block either.
- `nothing running to stop` is answerable again after a retirement.
- `blocks_claim_submitted_ids_in_the_order_they_were_submitted` still passes unchanged:
  two submissions the shell runs in order match at the front, and nothing is retired.
- The echo is still not output: no `Output` event carries it.

End to end, in `pipeline.rs`: a scripted session whose heading on the wire is the
transcript's echo, proving the text came from the far end through the real engine and
tracker.

Frontend, in `app.test.ts`: an echoed command line replaces the optimistic heading; a
`CommandStarted` with `null` leaves it alone; a submit ack resolving *after* an echoed
`CommandStarted` does not overwrite it.

## Acceptance criteria

1. `cargo test --workspace` green; `cargo clippy --workspace --all-targets` clean under
   `-D warnings`; `cargo fmt --check` clean; `npm test` green.
2. Protocol bindings regenerated and the drift guard green.
3. The pump's claim is decided by evidence or by FIFO, and never by a timeout, a prompt
   or a similarity score.
4. Module role declarations and the visibility ladder unchanged; `acter-core` still names
   no adapter crate.
5. **Accessibility checklist in the PR body**: the drift scenario driven through the real
   backend with NVDA, confirming a block's heading is the command whose output is under
   it, and that the buffer's newest heading is the running command.

## Out of scope

- **Any rule that retires an unclaimed id without evidence** — decision 3.
- **An event meaning "this line never ran"** — decision 4.
- **The alternate-screen rule** — decision 5.
- **Fixing correlation for a shell that does not echo.** There is nothing to read there,
  and B6's FIFO remains the answer.
