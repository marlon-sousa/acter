# 52.1 — a prompt is reported when it is drawn

Roadmap entry 52.1, lane 1.

## What was observed

Found on 2026-09-23 while comparing NVDA's reading of the V1 build with main's (PR #71).
- **Setup:** NVDA 2026.1.1 through the bridge; the scripted fake with `default_transcript.json`;
  a saved connection starting in far-end line mode.
- **Steps:** Ctrl+Shift+K, `small`, Enter, `fail`, Enter, then reading the buffer.

The same steps gave three different orders for the `acter>` prompt paragraphs:
- (a) a prompt before the first heading and none after the last output;
- (b) each prompt after its command's output;
- (c) two prompts in a row before a third command, with none after its output.

A WebDriver dump showed that the page itself held each order. While typing, NVDA announced
`acter>` straight after Enter, before the command's output. Against a real PowerShell the
order was always prompt, heading, output, prompt.

## The cause

Read from the code on 2026-09-23:

- **`PromptDrawn` is sent only from `prompt_finished`,** which runs when a line arrives in
  another region, or once per tracker event inside `feed`. A read that produces no tracker event
  never calls it.
- **The scripted fake sends `A`, `acter> ` and `B` as three separate reads,** one per delivery
  (`Chunking::Whole`). `B` with no open block produces no event, so the prompt stays pending in
  `drawing`.
- **It goes out only when the next submission's echo arrives,** in `Region::CommandLine`. So the
  backend reports each prompt *after* the user pressed Enter at it. The pipeline test at
  `crates/acter-transports/tests/pipeline.rs` pins that order today: no prompt event before the
  first submit, then `prompt("acter>")` before `started("small")`.
- **The frontend then races that late `PromptDrawn` against the submit ack,** which travels as the
  invoke response, not on the event channel. `appendPrompt` always appends at the end of
  `#results`, and the first of the ack and `CommandStarted` appends the block. Whichever arrives
  first decides where the prompt lands, and it can differ from one command to the next. That
  gives (a) and (c). The prompt drawn after the last command is never sent until another command
  is submitted, which gives the missing trailing prompt.
- **PowerShell writes `D`, `A`, the prompt and `B` as one string,** so the same read ends outside
  the prompt region and `PromptDrawn` goes out straight after `CommandFinished`. The stall depends
  only on where reads split, so a real pseudoconsole that split `B` into its own read would hit it
  too.

## Decisions

1. **A finished prompt is reported at the end of the read that finished it.** After `feed` has
   processed a read's events, if the tracker is no longer in `Region::Prompt` and a prompt is
   pending, the pump calls `prompt_finished`. A `B` arriving alone then sends `PromptDrawn` at
   once, just as a single-read prompt does today. Nothing else about the prompt text changes.
2. **The frontend is unchanged.** With the prompt reported when it is drawn, it reaches the page
   before the user can press Enter at it. That was the order PowerShell already gave.
3. **Typing ahead is out of scope.** A user who types the next command while one is still
   running can still see the next prompt land after that command's heading, because
   `appendPrompt` carries no command id. It is recorded here, and it becomes an entry of its own
   if anyone meets it.

## Files touched

- `crates/acter-core/src/services/session.rs` and its tests
- `crates/acter-transports/tests/pipeline.rs`, whose expected order changes to what the shell

- `docs/ROADMAP.md` (flip 52.1 to Done)

## Acceptance criteria

1. A session test feeds `A`, the prompt text and `B` as three separate reads, and expects
   `PromptDrawn` after the third read, before any submission.
2. The pipeline tests expect, for each command:
   - `started`, output and `finished`;
   - then `prompt("acter>")` for the prompt drawn after it;
   - and the first prompt before the first submission.
3. Every other Rust, UI and e2e test passes.
4. Driven over WebDriver against the fake, five runs of the V1 steps all give prompt, heading,
   output, prompt, with a prompt last.
