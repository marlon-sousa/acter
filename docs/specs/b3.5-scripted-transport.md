# Spec: PR B3.5 — the `Transport` port and the scripted byte-level fake

Agreed in conversation 2026-08-18. Lane 2, entry B3.5. Delivers the driven port every
byte source will implement, its first implementer — a scripted transport that behaves
like a shell — the transcript format both cargo tests and manual sessions replay, and
the first test that runs a real transcript through the real engine, the real tracker,
the real pacing policy and the real actor.

## Why now / relation to the roadmap

- A3's fake implements `SessionApi`, the *driving* port at the top of the stack. Every
  manual NVDA session so far has validated the frontend against a hand-written event
  stream and nothing below it: not the pacing policy, not the actor, not the tracker,
  not the engine. This entry moves the fake to the bottom of the stack, where the whole
  domain runs above it.
- Fake only what cannot run deterministically in CI — a shell on a PTY. Everything
  above it is real.
- Three things it buys that no other entry does. Every lane-2 component gains a caller
  the moment it lands (the lesson B1.5 recorded about B1). DESIGN's reliability model
  becomes testable end to end — a marker split across two reads, a forged marker, a `D`
  that never arrives — which an event-level fake structurally cannot produce. And the
  fake becomes a request/response loop that answers a written command line with real
  markers, which turns A3.2's blocked input-model question into something that can be
  tried rather than argued.
- B3 left two things with no consumer: `TerminalEngine::take_replies`, whose whole
  reason for existing is that device-query answers must be written back to a transport,
  and the item stream itself. This is the entry that closes both loops.

## Design decisions this spec makes

1. **The port is push, and the adapter owns its reading strategy.** `Transport` has
   `start(&mut self, bytes: Sender<Vec<u8>>)`, `write(&mut self, bytes: &[u8])` and
   `resize(&mut self, columns: u16, screen_lines: u16)`. Reads arrive on the channel the
   caller supplies; the end of a session is that channel closing, not an error variant.

   The adapter decides *how* it reads, because that is exactly the knowledge that
   differs between implementers and nothing above it can express: ARCHITECTURE already
   decides blocking PTY reads get a dedicated thread feeding the session channel (B4),
   the scripted transport runs a `Clock`-driven loop (decision 3), and an SSH transport
   later is a future. Sync and dyn-compatible, per ARCHITECTURE's rule for port traits —
   no `async_trait` machinery — and fire-and-forget on the read side, the shape
   `EventSink` already has in the other direction.

   Rejected: a blocking `read(&mut self, buf) -> io::Result<usize>`. It is a smaller
   trait, but it moves thread ownership up into the domain side and forces a future
   async transport to pretend to block.

   `write` and `resize` return `Result<(), TransportError>`: a write can genuinely fail
   (the pipe is gone) and the caller must be able to say so out loud. `TransportError`'s
   `Display` strings are speakable sentences, which CLAUDE.md makes a domain requirement
   rather than polish. `acter-core` gains `thiserror`, which ARCHITECTURE already
   prescribes for library crates.

2. **The scripted transport lives in `acter-transports`.** It is a `Transport`
   implementer, DESIGN's Decided item makes the scripted session a permanent supported
   session kind rather than scaffolding, and B4's `LocalPty` lands beside it in the crate
   ARCHITECTURE names for exactly this. The crate gains its first dependencies:
   `acter-core` (the port), `serde` and `serde_json` (the transcript), `tokio` (its
   loop).

   Rejected: `acter-app`, which the roadmap sketch suggested and which would match A3's
   precedent of keeping the fake beside the composition root. A3's fake is scaffolding
   with a retirement date; this one is a product feature, and ARCHITECTURE asks
   `acter-app` to stay as thin as possible.

   The A3 fake is not touched, moved or retired here. It stays the default backend until
   B6 switches it, so the slowest feedback loop in the project never goes dark.

   **What this entry does to the shape of "fake", recorded because it decides B6's
   scope.** Today faking is a *service*-level concept: `FakeSessionService` implements
   `SessionApi` and invents protocol events, so a fake session and a real session are two
   different services. After this entry, faking is a *transport* choice. The service, the
   actor, the tracker, the engine and the pacing policy are the same code whether bytes
   come from `ScriptedTransport` or from B4's `LocalPty`; only the injected adapter
   differs. So there is exactly one session service from B6 onward, and DESIGN's Decided
   "the scripted fake session is a permanent supported session kind" survives unchanged —
   it becomes a profile that selects a transport, which is what a profile was already
   defined to be. `FakeSessionService` and its baked-in scenario shapes are therefore
   deleted at B6 rather than maintained beside the real service; what B6 deletes is the
   imitation, not the scenarios, because this entry has already moved those into data.

3. **Delays come from the `Clock` port, never from sleeping.** `ScriptedTransport` holds
   `Arc<dyn Clock>` and waits on `Clock::timer`. With B1.5's fake clock, a fixture's
   timing is honored *exactly* in cargo tests at zero real time; with `SystemClock`, the
   same code is a manual session paced for a human ear.

   Rejected: `tokio::time` directly. An adapter is allowed to touch the world, but then
   every timing test either sleeps for real — B1.5's acceptance criterion 2 already
   records that Windows timer granularity makes short waits unassertable — or drops the
   timing, and for `tail`, `burst` and `forever` the timing *is* the thing under test.

4. **The fake is a shell-shaped request/response loop, not a linear tape.** On `start`
   it emits prompt-start (`A`), the prompt text, and command-line-start (`B`). On a
   written line it echoes the line back — as a real shell's terminal does — then emits
   `C`, the scripted output steps, `D` with an exit code, and the next prompt.

   This is what B2's regions actually require: `Prompt` is A..B, `CommandLine` is the
   B..C echo, `Output` is C..D. An event-level fake cannot produce a prompt or an echo
   at all, which is why DESIGN's echo exclusion has never once been exercised against
   something that echoes. It is also what makes A3.2 answerable: the fake replies to
   bytes, so whichever input model wins, the other end of the wire already exists.

   Scenario selection stays A3 decision 4: the submitted line picks the rule, anything
   unrecognized echoes and returns to the prompt.

   **Amended during implementation: the markers around a command's output belong to the
   rule's steps, and only the prompt and the echo are the transport's.** The sentence
   above reads as a description of the byte stream, and it is; but taken as a division of
   labour it cannot express three of this spec's own scenarios — `forever` has no `D` at
   all, `stop`'s `D` carries no exit code, and `fail`'s carries a nonzero one — so a
   transport that emitted `C` and `D` itself would have to be told when not to. So a rule
   writes every marker it wants, `C` first and `D` last, and the transport contributes
   exactly the two things a transcript cannot know: the echo, which is the submitted line
   and therefore not authorable in advance (decision 6 excludes templating), and the
   prompt. `on_start` is that prompt sequence, replayed after every rule that runs to
   completion — which is what makes the loop a loop, and what leaves `forever` sitting at
   no prompt at all, correctly.

5. **One transcript format, two consumers, and steps are read boundaries.** A transcript
   is JSON: an `on_start` step list, a list of rules each with a match and its own step
   list, and a default rule. A step is a delay range plus one payload.

   Each step is one delivery to the caller — one `read`. That is what makes chunking
   scriptable: a marker split across two reads is two steps with zero delay, which is
   DESIGN's reliability case and the thing B3's own test had to hand-write.

   Two consumers, exactly as the roadmap promised. A cargo test parses a transcript and
   feeds its bytes straight to the engine — no transport, no runtime, no clock — which
   is ARCHITECTURE's golden-transcript tier. The scripted transport replays the same
   file as a live session. One format, one parser, no second dialect for tests.

6. **Marker shorthands expand to real bytes before anything is written.** A payload is
   one of: `text` (a UTF-8 string, so JSON's own escapes reach the byte stream), `marker`
   (`A`, `B`, `C`, or `D` with an optional exit code), `base64` (arbitrary bytes), or
   `file` (a relative path to a raw capture — what B5 produces).

   The shorthand is authoring convenience, never a bypass: it expands to the real
   sequence, terminated with BEL, and the recognizer in `acter-term` sees the same bytes
   a PowerShell prompt hook would emit. A fixture that wants the ST terminator, a
   malformed marker, or a forged one writes the bytes itself — and the reliability
   fixtures do exactly that. Rejected: raw payloads only, which makes every hand-authored
   fixture an escape-code puzzle and unreadable aloud; and a line-oriented DSL, which
   buys readability at the price of a hand-written parser and a second config language
   beside A3's JSON.

   Delays reuse A3's `DelayRange { min_ms, max_ms }` shape: equal bounds are
   deterministic, unequal bounds are sampled for organic manual pacing.

   Two extras, and no more: `repeat` on a step (a count, or endless — `forever` and
   `tail` need it) and `interrupts` on a rule (decision 7). Text templating is
   deliberately excluded, carrying forward A3 decision 8's second scope line: this is a
   parameterized script, not a step-scripting DSL. Additive later if experimentation
   demands it.

7. **An interrupt is a rule, and this spec takes no position on who sends it.** A rule
   may be marked `interrupts`, meaning it cancels whatever sequence is in flight and runs
   instead. That covers a written `0x03` exactly as a real shell would answer it, and it
   covers A3.1's literal `stop` line, without inventing stdin semantics the fake has no
   business having (A3 decision 7's deviation stands until the real domain arrives).

   Whether the frontend writes `0x03` on Ctrl+C or sends something else is A3.2's
   blocked question. This entry does not decide it; it makes both answers testable.

8. **Correlation stays B6's, so the pipeline test uses deliberately dumb glue.** The
   chain is bytes into `AlacrittyEngine::advance`, `TerminalItem`s into
   `BoundaryTracker::observe`, `BoundaryEvent`s into `SessionInput`, and the actor out to
   a recording `EventSink`. The second-to-last hop needs a `CommandId`, and B2 decision 5
   and the B6 entry both assign that — with the integration grace period — to B6, because
   it needs the queue of submitted commands.

   So the test glue mints ids in submission order at `BlockStarted`, drops every region
   except `Output` (echo exclusion, the one-line caller filter B2 decision 2 promised),
   and drains `take_replies` after each advance, writing the bytes back to the transport.
   It is fifty lines in a test file, it is named as B6's to replace, and it is *not* a
   component: no service, no controller, nothing new in `acter-core`.

   **Amended during implementation: the glue needed two more rules than "drop every region
   but `Output`", and both are B6's to inherit rather than accidents of the test.** First,
   a `Line` item carries no line ending — the engine emits one item per line of the grid —
   while the pacing policy counts lines in the text it is handed, so the glue inserts a
   separator when consecutive output items belong to different lines. Without it `big`'s
   thirty lines measure as one and no threshold is ever crossed, which would have made
   this entry's headline claim vacuous. Second, revisions have to be filtered, not
   ignored: taking every `Settled` alongside its `Appended` says each line twice, and
   taking none loses the lines that scrolled out of the screen area inside a single read,
   which arrive settled and complete having never appended. The glue therefore takes an
   append always, a settlement only when the line was rewritten since its last word or was
   never seen at all, and a rewrite never — the split DESIGN's separate-paths decision
   already describes, applied for the first time. Its identity bookkeeping deliberately
   spans regions, because a block's lines settle while the region is still `Output`,
   including the prompt row the echo was written onto; recognizing that row is what keeps
   the echo out of the command's output.

9. **The ten A3 scenarios are translated here, as data — and their verdicts stop being
   scripted.** They are a fixture file, so translating them now is what actually proves
   the format expresses timing, floods, endless streams and alt-screen. B6 then only
   wires.

   The consequence to state plainly, because it is the entire point of the entry: A3's
   fake *scripted* every verdict, and this one scripts none. `TooBig`, the patience
   announcement, the babble guard and the auto-read decision are all computed by B1's
   real policy from real text and real timing. That means the built-in transcript's
   numbers must be chosen against `PacingConfig`'s defaults rather than copied from A3's
   config, and it means the manual matrix at B6 tests the policy for the first time
   instead of testing a script that imitates it.

10. **No user-facing surface, so no accessibility checklist.** Nothing in this PR runs at
    startup: `ScriptedTransport` is `pub` from its crate and constructed by tests until
    B6 wires it. That is the `SystemClock` shape B1.5 landed knowingly, and it is stated
    here rather than discovered — the difference from the shape B1 refused to create is
    that the implementer ships in the same PR as the port, and its consumer is one entry
    away, not five.

## The scenario translation

Every A3 scenario, expressed in bytes. The names are unchanged, because DESIGN's
permanent-session-kind decision is about the scenarios, and only the altitude they were
written at was wrong.

- `small` — one output step, one short line, exit 0.
- `big` — one step of N numbered lines, exit 0. N is chosen so B1's threshold produces
  `TooBig`; the *verdict* is no longer in the fixture.
- `fail` — one short error line, `D` with a nonzero exit code.
- `slow` — three steps, one phase each, on a chunk interval.
- `forever` — two opening steps, then an endless `repeat` of a small step. No `D` ever,
  which is DESIGN reliability case 1 and now produces the patience announcement from the
  policy rather than from a script.
- `nano` — a step emitting the alt-screen enter sequence, an alt-screen repaint, then the
  leave sequence and `D`.
- `tail` — a counted `repeat` of one small step on a sampled delay range.
- `burst` — one large step, then a counted `repeat` of small steps, then `D`.
- `speech` — one step carrying a long single-line phrase with a countable closing marker.
- `stop` — a rule marked `interrupts`, emitting the interrupt echo and a `D` with no exit
  code.
- anything else — the default rule: echo the line, `D` with exit 0.

An eleventh rule, added during implementation and required by decision 7 rather than a
new idea: a written `0x03` matches an interrupting rule of its own, with the same steps as
`stop`. That is what makes both answers to A3.2 already have the other end of the wire —
whichever bytes the frontend decides Ctrl+C sends, one of these two rules is already
waiting for them.

## Deliverables

### `acter-core`

- `ports/driven/transport.rs` — `Transport` (role: port, driven) with `start`, `write`
  and `resize` per decision 1, and `TransportError` with speakable `Display` strings.
  Documented against decision 1: why reads are pushed, why the end of a session is a
  closed channel rather than an error, and who owns the reading thread.
- `Cargo.toml`: `thiserror`.
- `lib.rs`: re-export `Transport` and `TransportError`.

### `acter-transports`

- `Cargo.toml`: `acter-core`, `serde`, `serde_json`, `tokio` (`sync` and `rt` — it spawns
  its own reader, as `SystemClock` spawns its own sleep); dev-dependencies `acter-term`
  and `tokio` with `macros`, for the pipeline test.
- `scripted/transcript.rs` (role: entity/value) — `SessionTranscript`, `Rule`, `Step`,
  `Payload`, `DelayRange`; parsing, validation (`min_ms` no greater than `max_ms`, a
  non-empty rule list, a `file` payload that resolves), and payload expansion to bytes
  including the OSC 133 shorthand. Pure data: no clock, and no I/O beyond resolving a
  `file` payload relative to the transcript.
- `scripted/default_transcript.json` — the ten scenarios, `include_str!`-ed as
  `SessionTranscript::builtin()` so a dev run needs no file, mirroring A3's built-in
  defaults.
- `scripted.rs` (role: adapter) — `ScriptedTransport`, holding the transcript, an
  `Arc<dyn Clock>` and the in-flight sequence. `start` spawns the emission loop and emits
  the opening prompt; `write` matches a rule and queues its steps, cancelling first if
  the rule interrupts; `resize` is accepted and recorded (a scripted session has no
  reflow, and the recorded value is what a test asserts against).
- `lib.rs`: re-export `ScriptedTransport` and `SessionTranscript`.

### Fixtures

`crates/acter-transports/tests/fixtures/` — the reliability transcripts, hand-authored at
byte level: a marker split across two steps, a forged `D` mid-output, a session whose `D`
never arrives, a session with no markers at all, an alt-screen enter and leave, and a
device-query transcript.

A seventh rides with them: a transcript whose prompt is a `file` payload, plus the raw
capture it names. Not a reliability case — it is the only way the `file` payload and its
resolution-relative-to-the-transcript rule are exercised before B5 produces the first real
capture.

### `acter-term`: an amendment, and the first defect this entry's caller found

**Amended during implementation: entering the alternate screen anchors the extractor's
next scan at the top of the new grid, not at the cursor.** This spec listed no `acter-term`
deliverable, and this is one — it is here because the pipeline test found it, which is the
argument the "why now" section makes for the whole entry.

B3 starts a fresh extraction epoch at the cursor after any event that renumbers rows,
which is right for a resize and right for the normal screen coming back: the rows above
the cursor hold text already emitted, and anchoring higher would re-emit all of it. It is
wrong for the alternate screen, which mode 1049 hands over blank and which every
full-screen program then paints from row zero after an `ESC[H ESC[2J` — so every row above
wherever the cursor happened to be was dropped. For `nano` that is its title bar; for
`vim`, most of the first screenful. No B3 test caught it because none fed the engine a
real repaint; the `nano` scenario did, on its first run.

Losing text is this product's cardinal defect, so it is fixed here rather than filed:
`Extractor::reanchor_to_top` for the entry case, `reanchor` unchanged for the other two,
and a regression test in `acter-term` beside B3's own alt-screen tests. One existing B3
test changes with it — a program that switches screens without homing the cursor now emits
the blank first row it genuinely left above its text, which is the extractor's own
"vertical spacing is structure" rule and is the honest reading of a fresh grid.

## Tests

Unit tests inline (ARCHITECTURE tier 1) plus the fixture-replay tests (tier 3). Nothing
sleeps; every delay is the B1.5 fake clock.

- **Transcript parsing:** a full file round-trips; the built-in transcript parses and
  every scenario name resolves; an inverted delay range is rejected loudly; an unknown
  payload kind is rejected; each payload kind expands to the exact bytes expected, marker
  shorthand included.
- **The transport as a shell:** `start` emits `A`, prompt text, `B`; a written line is
  echoed, then `C`, the steps, `D`, and the next prompt; an unrecognized line takes the
  default rule; the delays requested from the clock are exactly the transcript's; a
  counted `repeat` emits exactly N times and an endless one keeps going; an interrupting
  rule cancels an in-flight sequence *while it is waiting*, not after its next step (the
  trap A3.1 already hit and fixed once); a write after the transcript ends is an error
  with a speakable message.
- **Steps are read boundaries:** a marker split across two zero-delay steps arrives as
  two reads and is still recognized as one marker downstream.
- **The pipeline, transcript in and recorded events out:** the happy path produces
  `CommandStarted`, `Output` events carrying only C..D text — the prompt and the echoed
  command line are absent, which is DESIGN's echo exclusion tested for the first time
  against something that echoes — and the command's end with its exit code.
- **The reliability model, one test per DESIGN case:** the split marker; a forged `D`
  inside output; a command whose `D` never arrives, which produces the patience
  announcement from the real policy after the real patience window on the fake clock; a
  session with no markers, which stays `Unstructured` and never reports integration.
- **Alt-screen through the whole stack:** entering emits the transition in stream order,
  and the actor sees it as `AltScreenEntered`.
- **The device-reply loop closes:** a transcript emitting a cursor-position query causes
  the glue to write the engine's answer back, and the transport records it. This is
  `take_replies`' first consumer.
- **A representative subset of the ten scenarios end to end:** `small`, `big`, `fail`,
  `nano` and `stop`, asserted as `SessionEvent` sequences. The remaining five are
  asserted at transcript level — they parse, match, and request the delays they claim;
  their audible behavior is B6's manual matrix.

## Acceptance criteria

1. `cargo test --workspace` green; `cargo clippy --workspace --all-targets` clean under
   `-D warnings`; `cargo fmt --check` clean.
2. Nothing in the test suite sleeps or reads the real clock: every scripted delay is
   driven by the fake clock, and the full pipeline test completes in milliseconds.
3. `acter-transports` depends on `acter-core`, `serde`, `serde_json` and `tokio` only;
   `acter-term` appears as a dev-dependency and only in the pipeline test.
4. Module role declared on the first line of each new module's `//!` comment; the
   visibility ladder holds; only `ScriptedTransport` and `SessionTranscript` are
   re-exported.
5. No protocol change, so no binding regeneration and no frontend change: the A3 fake is
   still the default backend and the app behaves exactly as it did before this PR.
6. The built-in transcript expresses all ten scenarios, and its numbers are chosen
   against `PacingConfig`'s defaults rather than copied from A3's config (decision 9).
7. ROADMAP and ARCHITECTURE amended as listed. No accessibility checklist, for the reason
   in decision 10, stated in the PR body.

## Out of scope

- **Command-id correlation, the integration grace period, and wiring any of this into the
  app** — B6, which is also where the default backend switches and where the ten
  scenarios first become audible.
- **`LocalPty` on ConPTY** — B4. `Transport` exists after this PR, so B4 is a second
  implementer, not a new seam.
- **Capturing real transcripts and the PowerShell injection snippet** — B5, which is the
  first producer of a `file` payload.
- **Retiring the A3 fake** — B6's, once the byte path is the default, and a deletion
  rather than a migration for the reason in decision 2. `Output.read_mode`,
  `CommandStillRunning` and failure-via-`CommandFinished` are A6's.
- **Deciding A3.2's input model.** The fake answers bytes; which bytes the frontend sends
  is still that entry's question.
- **A step-scripting DSL, text templating, and stdin to a running program** beyond the
  interrupt rule of decision 7.
