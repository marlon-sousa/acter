# B6.2 — What the far end said before its first marker

Roadmap entry 27.4. Agreed in conversation 2026-08-27, from the measurement recorded in that
entry. Depends on nothing; it is a change to one function in `SessionService`'s pump.

## What a listener met

Reported by the user on 2026-08-26 — *"on connection, I heard no prompt"* — and measured on
2026-08-27 by `ssh_rig.rs`, `what_a_session_says_when_it_has_just_connected`, which builds the
whole pipeline the window has and records every `SessionEvent` the frontend would receive.

In six seconds after connecting to the rig, the frontend received two events and no output at
all: `ConnectionChanged { state: Connected }`, then `IntegrationUnavailable`. The far end had
drawn `acter@acter-ssh:~$` well before that, and had printed a `Last login:` line in front of
it. None of it reached the buffer, so there was nothing to go back and review either.

**The first answer given was wrong and the user's rejection of it was right.** That answer was
that an unintegrated session is silent by design. It is not: cmd is unintegrated for *output*
and its prompt is still heard, so "unintegrated" means something specific about block
structure and has never meant silence anywhere else in this product.

## Where it actually was

`Pump::wants` decides whether a line's text is forwarded, and it had two arms where the domain
has three states:

- `Integration::Unintegrated` wanted `Region::Unstructured`.
- `Integration::Pending` and `Integration::Integrated` shared an arm that wanted `Output`, or
  `Output | Prompt` for a shell whose markers stop at `B`.

`Pending` is the state every session starts in and the state an unintegrated session stays in
for the whole grace period — five seconds by default. Before the first marker the tracker
labels every line `Unstructured`, which is precisely what that shared arm did not want. So the
text was not held, not queued, not rendered: `due` accounted for it and the gate dropped it.

That is the whole defect. It is one missing arm, and it was invisible because it only bites a
far end that never marks anything — which until B9 was a far end this product did not have.

## Decisions

### 1. A session that has not been told yet is its own case

`Pending` gets its own arm: unstructured text is wanted, and so is anything the marked filter
wants. The marked half cannot fire today, because the first marker of a session resolves
`Pending` to `Integrated` in the same batch it is seen in — but it is spelled out rather than
relied upon, so the filter's correctness does not rest on the order of two arms in
`Pump::feed`.

The filter for a session that *has* been told moves to `Pump::marked`, unchanged. B4.5's
reasoning about a prompt being content in a shell that emits no `D` travels with it.

### 2. The prompt arrives as a block nobody submitted, which is machinery that already exists

With no block open, `Pump::hold` finds no pending submission, spills, and `Pump::publish` calls
`Pump::unclaimed` — a fresh `CommandId`, a `CommandStarted` with no command line, and the text
as its output. That path was built for a shell's banner (B4.5) and needed no change; what
changed is that an unintegrated session now reaches it at all.

Two consequences, both intended and both asserted. The block has no heading, which B4.9 already
decided renders no heading element, so heading navigation does not gain a dead end. And it
spends the session's first `CommandId`, so the first command a user submits is `CommandId(2)`.

### 3. It is read aloud, not merely rendered

The text goes through the ordinary pacing path, so a listener hears the prompt on connecting
rather than having to go and look for it. That is the behaviour the user asked for, and it is
what the rest of the product already does with text that arrives in a block.

### 4. This does not make an unintegrated session integrated

`IntegrationUnavailable` still fires when the grace period expires, and still means what it has
always meant. What it stops doing is explaining an emptiness that had nothing to do with
integration.

## What this changes for shells that were already working

Nothing measured, and one thing worth naming. A shell that prints a banner before its
integration snippet runs now has that banner forwarded, where it used to be discarded. Measured
against the real suites on 2026-08-27: `real_session.rs` (cmd, both PowerShell editions, WSL
bash, a container, a nested shell) is unchanged and green, because those shells' markers arrive
in the first batch. The banner path is covered by a unit test rather than by a real shell,
since no shell currently in the suite prints one.

## Files touched

- `crates/acter-core/src/services/session.rs` — `Pump::wants` gains the `Pending` arm,
  `Pump::marked` is extracted, and two unit tests.
- `crates/acter-transports/tests/pipeline.rs` —
  `a_session_with_no_markers_degrades_honestly_instead_of_going_silent` asserted the defect and
  now asserts the fix.
- `crates/acter-transports/tests/ssh_rig.rs` —
  `what_a_session_says_when_it_has_just_connected` becomes an assertion rather than a printout.
- `docs/ROADMAP.md` — 27.4 to Done.

## Definition of done

- [x] A session with `Full` markers forwards what the far end said before any marker arrived,
      inside the grace period, in a block of its own.
- [x] A banner printed before the markers is kept, and the session still integrates, still
      closes its blocks on `D`, and still excludes the prompt and the echo.
- [x] The unmarked pipeline test asserts the prompt, the block, and the flag, in that order.
- [x] The SSH rig records the prompt reaching the frontend and being read aloud.
- [x] `cargo fmt`, `cargo clippy --workspace --all-targets`, `cargo test --workspace`, the
      `#[ignore]`d real-shell and SSH-rig suites, and `npm test` in `ui/` all clean.

## Accessibility checklist for the PR body

- [ ] Connecting to an SSH host reads the prompt aloud, once, without the user doing anything.
- [ ] The buffer holds that prompt afterwards, and heading navigation does not stop on an empty

- [ ] "No shell integration set up on this host" is still said, and is said after the prompt
      rather than instead of it.
- [ ] Connecting to cmd, to PowerShell and to WSL bash sounds as it did before.
