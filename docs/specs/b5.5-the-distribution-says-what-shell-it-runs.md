# B5.5 — The distribution says what shell it runs

Roadmap entry 23.8. Agreed in conversation 2026-08-27. Depends on **B5.3** for the WSL adapter
and the `InstalledShells` port, on **B9** decision 7 for the shape this borrows, and on
**B6.2**, which is what makes an unintegrated WSL session audible at all.

## What is assumed today

`wsl.exe` is a client, not a shell. What it starts is whatever login shell the distribution's
account is configured with, read from that distribution's own passwd. `Wsl::launch` injects
bash's `PROMPT_COMMAND` and `WSLENV` regardless, and `Wsl::markers` answers `Full`.

An account using zsh, fish, dash or anything else gets an injection its shell never reads.

## What is not wrong with it, and this matters

`ShellMarkers::Full` does not mean "this shell is integrated". It is the same optimistic claim
`Plain` and `far_end::over_ssh` make, and the grace period is what contradicts it — so a
zsh distribution already degrades honestly rather than forging markers. The safety property is
in place and this entry does not change it.

**Two things are missing, and neither is safety.** The user is told late — five seconds, the
whole grace period — and told nothing: a generic `IntegrationUnavailable` with no subject,
which is exactly the bare sentence 27 objected to for SSH and fixed there by naming the far
end. And an injection is pushed into a shell we have no reason to believe reads it.

## Decisions

### 1. Ask the distribution, once, on its own

Another `wsl.exe` invocation with its output captured — not a line typed into the session,
which would be a command nobody typed appearing in the buffer, and not a channel or a protocol,
because WSL needs neither. This is the cheap half of B9 decision 7 and it buys the same thing.

The question is the account's login shell, read the way the far-end probe reads it:
`wsl.exe -d <name> -- getent passwd $USER`, falling back to `sh -c 'echo $SHELL'` where
`getent` is absent. The **basename** of the last field is the answer; a full path is what
passwd stores and is not what a user hears.

### 2. It belongs on `InstalledShells`, beside the list it is about

"Which shell does this distribution's account use" is the same kind of question about the same
machine as "which distributions exist", asked of the same client. `InstalledShells` already
shells out to `wsl.exe -l -q` and is the one module in `acter-shells` that touches the world;
a second `Command` there is the port doing its job rather than a new seam.

### 3. Advisory, never a gate, and bounded

For 23.7's reason: the probe sits in the seconds before there is a prompt, which is already the
worst place in this product to add work. It runs with a deadline; a probe that fails, hangs or
answers with something that is not a shell name costs the session nothing and produces the
unnamed sentence in decision 5. It never delays the session's first byte — the session starts,
and the probe's answer reaches `ShellFacts` before the window needs a sentence, exactly as
B9's does.

**Per connection, not per row.** Asking at connect-list build time would mean one `wsl.exe` per
distribution every time the Connect dialog opens, which is worse in the place a listener is
already waiting.

### 4. Match, and fall back to the code that already exists

`adapter_for` returns `Plain` for anything this crate does not recognise, and `Plain` is
exactly "start it as it stands, inject nothing, claim nothing". So the rule is three states:

- **Measured** (bash): integrated as it is today, injection and all.
- **Known of but unmeasured** (zsh, fish, dash, sh): started with no injection, unintegrated,
  and *named*.
- **Unrecognised, or no answer**: unintegrated, unnamed.

**The identity may be guessed from the name; the injection may never be.** B5.3's bash program
cost real measurement — a `DEBUG` trap cannot remove itself from inside a function, and the
version built on the wrong assumption emitted four `C` markers per command. Knowing a far end
is zsh licenses saying so and nothing else until a zsh injection has been measured the same
way. That is a later entry.

### 5. Three sentences, and each says what it knows

- `Ubuntu 24.04, bash` — integrated, and nothing more is said, as today.
- `Ubuntu 24.04, zsh, with no shell integration set up in this distribution` — the SSH sentence
  one word different, and the difference is deliberate: over SSH the account belongs to
  somebody else, here it is the user's own and the fix is reachable.
- `Ubuntu 24.04, with no shell integration set up in this distribution` — no name, because
  nothing answered.

The sentence is built by the one function 27.5 established, so the status region and the
announcement stay the same string.

### 6. What this narrows, and what it does not

B5.3 decision 3 says a session whose `PROMPT_COMMAND` is clobbered by the user's own `.bashrc`
degrades quietly, and that stays true — clobbering is a different question and this probe does
not answer it. What changes is the assumption sitting beside it, which was never written down:
that the login shell is bash at all.

## Files touched

- `crates/acter-core/src/ports/driven/installed_shells.rs` — the login-shell question.
- `crates/acter-shells/src/installed.rs` — the `wsl.exe` invocation and its deadline.
- `crates/acter-shells/src/wsl.rs` — an adapter that injects only for a shell it was told is
  bash.
- `crates/acter-shells/src/far_end.rs` — the name-to-`ShellFacts` policy gains WSL as a second
  caller; the two transports keep separate measurement, since bash over WSL still answers no
  end-of-input byte and bash over SSH answers `0x04`.
- `crates/acter-app/src/container.rs` — the probe in the window between starting and
  `SessionService::start`.
- `crates/acter-transports/tests/real_session.rs` — an `#[ignore]`d test against a real
  distribution whose login shell has been changed.

## Definition of done

- [x] A distribution running bash behaves exactly as it does today, injection and markers
      included, and the existing WSL suite is unchanged. The four `#[ignore]`d WSL cases pass
      from a cold `wsl --shutdown`, including the one that asserts no
      `IntegrationUnavailable`.
- [x] A distribution whose login shell is not bash starts with no injection, is reported
      unintegrated, and is named in the connection sentence. Asserted where it is decidable
      rather than by reconfiguring somebody's distribution: `wsl.rs` proves the launch is
      bare for zsh, fish, dash, sh and nu, and `login_shell.rs` proves each of their passwd
      entries reads as its own name. What is left is hearing it, which the closing
      section below hands to the checklist.
- [x] A probe that fails or times out costs the session nothing and produces the unnamed
      sentence. Every failure is one `None`, and `Wsl` treats "nobody answered" and "not the
      measured shell" identically.
- [x] The probe's output cannot reach the terminal buffer, asserted rather than assumed:
      `nothing_the_probe_asked_reaches_the_session_a_listener_reads` runs a real WSL session
      and asserts that `getent`, `passwd`, `id -un` and `$SHELL` are in no rendered output.
- [x] `cargo fmt`, `cargo clippy --workspace --all-targets`, workspace tests, the `#[ignore]`d
      real-shell suite, and `npm test` in `ui/` all clean.

## Accessibility checklist for the PR body

- [ ] Connecting to a bash distribution names the shell and says nothing about integration:
      "connected to WSL: Ubuntu, bash" (amended — see amendment 4, which replaces "sounds
      exactly as it did before").
- [ ] Connecting to a non-bash distribution says which shell it is, in one sentence, without a
      five-second wait before anything is said about it.
- [ ] The status region read on demand says the same thing the announcement said.
- [ ] A distribution that is slow to start does not produce a second, contradicting sentence.

## Open, and worth measuring before the checklist

The grace period is five seconds, and on 2026-08-27 a **cold** WSL start exceeded it: the first
run of `a_real_bash_under_wsl_marks_the_boundaries_of_the_command_it_ran` after the VM had been
idle reported `IntegrationUnavailable` on a session that was fully integrated, and an immediate
rerun passed. That is roadmap 23.10 and not this entry's to fix, but it is the same session and
a listener would hear both sentences.


## Amendments made while implementing, 2026-08-29

### Amendment 1: the deadline is twelve seconds, and six was measured to be the worst number

Decision 3 said "bounded" and left the number open. Six seconds was tried first, on the
reasoning that it cleared roadmap 23.10's five. It failed on the developer's own machine, and
the failure was reproducible: the *first* `wsl.exe -- <command>` after an idle gap gave up at
the deadline, and the call immediately after it took 182 milliseconds.

Timed on 2026-08-29, Ubuntu 24.04 under WSL 2.5.7.0, with `wsl --shutdown` between the cold
runs. Warm: 148, 152, 165, 181, 188 and 206 milliseconds. Cold: 5.35, 5.49, 5.74 and 6.30
**seconds**. A six-second deadline lands in the middle of that spread, which is the worst
place for one to be — it makes a cold bash distribution a coin toss between being integrated
and being unnamed. Twelve is roughly twice the slowest cold start seen, which leaves the
deadline doing the only job it has: catching a distribution that is not coming up at all.

**And `wsl.exe -l -q` does not warm anything**, timed at 57 to 74 milliseconds cold and warm
alike. It is the first command run *inside* a distribution that boots it. That is why the
connect list stays cheap while this call cannot be, and it is a second, independent reason for
decision 3's "per connection, not per row".

### Amendment 2: the probe runs before the launch, not in B9's window

Decision 3 said the probe "never delays the session's first byte — the session starts, and the
probe's answer reaches `ShellFacts` before the window needs a sentence, exactly as B9's does".
That ordering is not available here, and the reason is decision 4's own: **what is injected is
part of the launch**. `ShellLaunch` carries the environment `LocalPty::spawn` is called with,
so "inject nothing into a shell that is not bash" has to be decided *before* the client starts,
where B9's probe only has to beat `SessionService::start`.

So the probe is the first thing the WSL branch does. What survives of the decision's intent is
what actually mattered: the cost is bounded, it is under a fifth of a second in every case but
the first, and on a cold machine it is barely a cost at all — **this call is what boots the
distribution**, so the session's own start then finds one that is up. The boot was going to be
paid either way. What a listener is told while it happens is roadmap 23.7's and 23.10's.

### Amendment 3: one invocation asks both questions, and it asks `id -un` rather than `$USER`

Decision 1 named two commands: `wsl.exe -d <name> -- getent passwd $USER`, "falling back to
`sh -c 'echo $SHELL'` where `getent` is absent". Two invocations would double the cost in the
one place decision 3 says not to spend it, so both travel in one line handed to `sh`:

    getent passwd "$(id -un)" 2>/dev/null || printf '%s\n' "$SHELL"

`$USER` is replaced by `$(id -un)` because `wsl.exe -- <command>` runs **no login shell**, so
the environment a login would have set up is not there and `$USER` is frequently unset — which
would make `getent passwd` list every account on the machine and the first line answer about
root. `id -un` asks the kernel and needs nothing to have been set up. `printf` rather than
`echo` for the SSH probe's reason: `echo`'s handling of backslashes and flags differs between
the very shells this is trying to tell apart.

### Amendment 4: a bash distribution is named too, and the checklist item was the thing that gave

Decision 5 writes the integrated sentence as `Ubuntu 24.04, bash` while the checklist asked
that a bash distribution "sound exactly as it did before" — and before, nothing named the
shell. The two cannot both hold. Decision 5 wins, because naming the shell is what this entry
is *called*: a listener connecting to a distribution now learns what they are talking to,
whether or not Acter integrated it. The checklist item is rewritten above to match.

The clause after the name is what still distinguishes the three cases, and `far_end_note` in
the composition root became one function over two inputs — the name, and where integration
would be set up if it is missing — so SSH's "on this host" and WSL's "in this distribution" are
one sentence-builder rather than two (roadmap 27.5's property, kept).

### Amendment 5: `far_end.rs` was not touched, and the transport matrix is asserted in `wsl.rs`

Files touched said `far_end.rs` "gains WSL as a second caller". It did not need to. That module
answers what a shell's *name* licenses for a far end **Acter did not start**; a WSL session is
one Acter starts, so `ShellFacts::of(&Wsl)` already carries the adapter's own answers and a
second policy function would have been dead weight saying what `Wsl::eof` says.

The property the line was protecting is real and is asserted, in the module that owns it:
`no_shell_under_wsl_has_a_measured_end_of_input_whatever_it_is_called` pins that bash under WSL
still ends on nothing while bash over SSH ends on `0x04`. Two cells of the matrix, two
measurements, and now a test that says so where somebody would go to tidy it away.

### Amendment 6: `adapter_for` stopped injecting into the WSL client, and that is the fix

Not in the files-touched list, and it is the heart of the change. `selection.rs` turns a
*name* into an adapter, and a name cannot say what a distribution's account runs — so
`adapter_for("wsl.exe")` now builds a `Wsl` with nothing claimed about its far end, which is
decision 4's third state rather than a degradation. Every WSL start in the product goes through
the composition root's new branch instead, `ACTER_SHELL=wsl` and `ConnectionKind::Wsl` included,
and each of them asks first.

`Wsl` itself carries the login shell in a field that every constructor takes, so the adapter
cannot be built without somebody having decided what to believe. Before this entry that field
did not exist and bash was the silent answer everywhere.

### Amendment 8: a distribution that is starting says so, in SSH's own words

**Raised by the user 2026-08-29**, on being shown the cold-boot measurement: *"we just need to
show a nice connecting status, like we do with ssh, then we are good to go."*

The spec settled what a listener hears when a connection *arrives* and said nothing about the
five to six seconds before it. That gap was invisible before this entry because there was
nothing to wait for — `LocalPty` spawns a process in milliseconds — and amendment 1 is what
makes it real: the probe is the call that boots a cold distribution.

So the WSL branch says one thing before it waits, through `SshQuestions::tell`, which is B9's
own mechanism and reaches a listener as `ConnectStep::Progress` exactly as "Connecting to
acter-ssh." does. It names the distribution the user chose — "Starting Ubuntu 24.04." — and
falls back to "Starting Linux." for a launch that named none, because asking WSL for its
default is deliberately not the same as this program deciding which one that is.

**One statement, not three.** SSH says three because it has three stages a listener can be at;
this has one thing to wait for, and "asking the distribution what shell it runs" would describe
Acter's internals rather than the user's wait.

**This does not close roadmap 23.7.** That entry is about the seconds after a session exists
and before its shell draws a prompt, which is a different silence with a different clock. What
this covers is the seconds before there is a session at all — and it covers them only for WSL,
because WSL is the only local far end with a wait worth narrating.

**A naming tension, recorded rather than fixed.** `tell` lives on `SshQuestions`, whose module
doc frames the port as SSH's. The method itself is documented as the general "progress while a
connection is being made", and `Unasked` already answers it for launches from the environment,
so using it here is the port working as written. Renaming the port would be a separate change
with its own blast radius.

### Amendment 7: this spec was already on main

The entry said the spec would travel with its implementation. It landed early, in A13's PR
(#45, 2026-08-27), so this PR carries the code, the amendments above and the entry flip.

## What implementing it did not settle

**The non-bash case has not been heard.** Every part of it is asserted — the reading, the bare
launch, the sentence — but on unit tests and captured bytes, because measuring it end to end
means reconfiguring a real distribution's login shell. The `#[ignore]`d real-shell test asks
this machine and gets `bash`, which is the case that had to keep working. Hearing zsh named is
the accessibility checklist's item and a human's to check.
