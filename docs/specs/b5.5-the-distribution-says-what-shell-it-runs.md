# B5.5 — The distribution says what shell it runs

Roadmap entry 23.8. Agreed in conversation 2026-08-27. Depends on **B5.3** for the WSL adapter
and the `InstalledShells` port, on **B9** decision 7 for the shape this borrows, and on
**B6.2**, which is what makes an unintegrated WSL session audible at all.

## What is assumed today

`wsl.exe` is a client, not a shell. What it starts is whatever login shell the distribution's
account is configured with, read from that distribution's own passwd. `Wsl::launch` injects
bash's `PROMPT_COMMAND` and `WSLENV` regardless, and `Wsl::markers` answers `Full`.

An account using zsh, fish, dash or anything else gets an injection its shell never reads.

## What is not wrong with it, and this matters

`ShellMarkers::Full` does not mean "this shell is integrated". It is the same optimistic claim
`Plain` and `far_end::over_ssh` make, and the grace period is what contradicts it — so a
zsh distribution already degrades honestly rather than forging markers. The safety property is
in place and this entry does not change it.

**Two things are missing, and neither is safety.** The user is told late — five seconds, the
whole grace period — and told nothing: a generic `IntegrationUnavailable` with no subject,
which is exactly the bare sentence 27 objected to for SSH and fixed there by naming the far
end. And an injection is pushed into a shell we have no reason to believe reads it.

## Decisions

### 1. Ask the distribution, once, on its own

Another `wsl.exe` invocation with its output captured — not a line typed into the session,
which would be a command nobody typed appearing in the buffer, and not a channel or a protocol,
because WSL needs neither. This is the cheap half of B9 decision 7 and it buys the same thing.

The question is the account's login shell, read the way the far-end probe reads it:
`wsl.exe -d <name> -- getent passwd $USER`, falling back to `sh -c 'echo $SHELL'` where
`getent` is absent. The **basename** of the last field is the answer; a full path is what
passwd stores and is not what a user hears.

### 2. It belongs on `InstalledShells`, beside the list it is about

"Which shell does this distribution's account use" is the same kind of question about the same
machine as "which distributions exist", asked of the same client. `InstalledShells` already
shells out to `wsl.exe -l -q` and is the one module in `acter-shells` that touches the world;
a second `Command` there is the port doing its job rather than a new seam.

### 3. Advisory, never a gate, and bounded

For 23.7's reason: the probe sits in the seconds before there is a prompt, which is already the
worst place in this product to add work. It runs with a deadline; a probe that fails, hangs or
answers with something that is not a shell name costs the session nothing and produces the
unnamed sentence in decision 5. It never delays the session's first byte — the session starts,
and the probe's answer reaches `ShellFacts` before the window needs a sentence, exactly as
B9's does.

**Per connection, not per row.** Asking at connect-list build time would mean one `wsl.exe` per
distribution every time the Connect dialog opens, which is worse in the place a listener is
already waiting.

### 4. Match, and fall back to the code that already exists

`adapter_for` returns `Plain` for anything this crate does not recognise, and `Plain` is
exactly "start it as it stands, inject nothing, claim nothing". So the rule is three states:

- **Measured** (bash): integrated as it is today, injection and all.
- **Known of but unmeasured** (zsh, fish, dash, sh): started with no injection, unintegrated,
  and *named*.
- **Unrecognised, or no answer**: unintegrated, unnamed.

**The identity may be guessed from the name; the injection may never be.** B5.3's bash program
cost real measurement — a `DEBUG` trap cannot remove itself from inside a function, and the
version built on the wrong assumption emitted four `C` markers per command. Knowing a far end
is zsh licenses saying so and nothing else until a zsh injection has been measured the same
way. That is a later entry.

### 5. Three sentences, and each says what it knows

- `Ubuntu 24.04, bash` — integrated, and nothing more is said, as today.
- `Ubuntu 24.04, zsh, with no shell integration set up in this distribution` — the SSH sentence
  one word different, and the difference is deliberate: over SSH the account belongs to
  somebody else, here it is the user's own and the fix is reachable.
- `Ubuntu 24.04, with no shell integration set up in this distribution` — no name, because
  nothing answered.

The sentence is built by the one function 27.5 established, so the status region and the
announcement stay the same string.

### 6. What this narrows, and what it does not

B5.3 decision 3 says a session whose `PROMPT_COMMAND` is clobbered by the user's own `.bashrc`
degrades quietly, and that stays true — clobbering is a different question and this probe does
not answer it. What changes is the assumption sitting beside it, which was never written down:
that the login shell is bash at all.

## Files touched

- `crates/acter-core/src/ports/driven/installed_shells.rs` — the login-shell question.
- `crates/acter-shells/src/installed.rs` — the `wsl.exe` invocation and its deadline.
- `crates/acter-shells/src/wsl.rs` — an adapter that injects only for a shell it was told is
  bash.
- `crates/acter-shells/src/far_end.rs` — the name-to-`ShellFacts` policy gains WSL as a second
  caller; the two transports keep separate measurement, since bash over WSL still answers no
  end-of-input byte and bash over SSH answers `0x04`.
- `crates/acter-app/src/container.rs` — the probe in the window between starting and
  `SessionService::start`.
- `crates/acter-transports/tests/real_session.rs` — an `#[ignore]`d test against a real
  distribution whose login shell has been changed.

## Definition of done

- [ ] A distribution running bash behaves exactly as it does today, injection and markers
      included, and the existing WSL suite is unchanged.
- [ ] A distribution whose login shell is not bash starts with no injection, is reported
      unintegrated, and is named in the connection sentence.
- [ ] A probe that fails or times out costs the session nothing and produces the unnamed
      sentence.
- [ ] The probe's output cannot reach the terminal buffer, asserted rather than assumed.
- [ ] `cargo fmt`, `cargo clippy --workspace --all-targets`, workspace tests, the `#[ignore]`d
      real-shell suite, and `npm test` in `ui/` all clean.

## Accessibility checklist for the PR body

- [ ] Connecting to a bash distribution sounds exactly as it did before.
- [ ] Connecting to a non-bash distribution says which shell it is, in one sentence, without a
      five-second wait before anything is said about it.
- [ ] The status region read on demand says the same thing the announcement said.
- [ ] A distribution that is slow to start does not produce a second, contradicting sentence.

## Open, and worth measuring before the checklist

The grace period is five seconds, and on 2026-08-27 a **cold** WSL start exceeded it: the first
run of `a_real_bash_under_wsl_marks_the_boundaries_of_the_command_it_ran` after the VM had been
idle reported `IntegrationUnavailable` on a session that was fully integrated, and an immediate
rerun passed. That is roadmap 23.10 and not this entry's to fix, but it is the same session and
a listener would hear both sentences.
