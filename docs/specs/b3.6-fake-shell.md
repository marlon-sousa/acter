# Spec: PR B3.6 — the fake shell and the fake pipe

Agreed in conversation 2026-08-19. Lane 2, inserted between B3.5 and B6. Splits
`ScriptedTransport` into the two things fused inside it — a **fake shell** that decides
what the far end says, and a **fake pipe** that decides how those bytes arrive — so the
two compose instead of being authored together in every fixture.

No change to `acter-core`. No new port. One adapter crate, refactored.

## Why now / relation to the roadmap

- B3.5 landed a fake that "behaves like a shell rather than playing a tape": it draws a
  prompt, echoes what was written, plays the matching rule, and draws the next prompt.
  That was the right discovery, and this entry finishes it — the thing it discovered is a
  *shell*, and it is currently welded to the pipe that carries its bytes.
- **The conflation is load-bearing, not cosmetic.** Read boundaries are authored into
  transcripts today: `Step`'s doc says a zero delay is how "a payload is split across two
  reads", and `split_marker.json` exists because of it. Splitting is a property of the
  pipe — of how a read happens to land — not of what the shell said. So DESIGN's "a
  marker split across two reads" is proven for exactly one hand-authored marker, when it
  should be provable for every marker in every fixture.
- **A shell trait is what the unintegrated case actually needs.** "Emits no markers" is
  not a script; it is a permanent property of the far end. Today it is
  `unmarked_session.json`, every step hand-authored, and it answers only the lines
  somebody thought to write down. A marker-less *shell* answers anything you type.
- **Before B6, not after.** B6 switches the default backend and runs the first real
  accessibility matrix against these fixtures. If the split lands afterwards, those
  fixtures and that matrix are authored twice. B6 adds only `interrupt` to this crate, so
  going first costs it nothing.

## Design decisions this spec makes

1. **The cut: what the far end says, versus how its bytes arrive.**

   To the shell:
   - the prompt sequence, at session start and after every completed answer;
   - the echo of what was submitted, and the line discipline that decides when written
     bytes *are* a submission — including the control bytes that carry no line ending;
   - which rule answers a line, and whether a submission interrupts what is in flight;
   - markers, exit codes, and the timing between deliveries. A command that dribbles
     output for a quarter of a second is the program being slow, which is far-end
     behavior.

   To the pipe:
   - how a produced byte stream is cut into reads;
   - the recording of what was written and of the last resize;
   - the far end going away.

   The clock stays with the pipe, for the reason in decision 2.

2. **`FakeShell` is a synchronous state machine; the pipe owns the clock and the task.**

   ```rust
   pub trait FakeShell: Send {
       fn greet(&mut self) -> Script;
       fn accept(&mut self, pending: &mut Vec<u8>) -> Vec<Submission>;
       fn interrupts(&self, submission: &Submission) -> bool;
       fn answer(&mut self, submission: &Submission) -> Script;
   }
   ```

   A `Script` is a sequence of deliveries, each a delay, a payload and a repeat — the
   timing-bearing byte stream the shell wants produced, **with no read boundaries in it**.

   Synchronous and runtime-free, which is this repo's established idiom for decision
   logic: B1.5 made the actor's decisions synchronous methods precisely so its contract
   could be asserted without a runtime, a sleep or a real clock, and a fake shell is the
   same kind of thing. It also means a shell implementer cannot accidentally acquire
   timing behavior of its own — every wait belongs to the pipe, which already holds the
   `Clock`, so the guarantee that nothing anywhere sleeps stays a property of one file.

   `accept` takes `&mut Vec<u8>` because line discipline consumes: it drains what it
   recognized and leaves the remainder, which is exactly what `submissions_in` does today.

3. **Read boundaries leave the transcript, and become a `Chunking` strategy.**

   The pipe holds a chunking strategy that cuts each delivery into reads:

   - `Chunking::Whole` — one delivery, one read. The default, and what every fixture means
     today once its read-splitting steps are merged.
   - `Chunking::Bytes(n)` — cut every delivery into reads of at most `n` bytes. `Bytes(1)`
     is the adversarial case: every marker, every escape sequence and every line arrives
     one byte at a time.

   This is a deliberate **removal of expressiveness**: a transcript can no longer say
   where a read ends. `split_marker.json` is therefore deleted rather than converted — the
   thing it tested becomes a dimension every other fixture is run under.

   **What this buys, stated precisely so it is not overclaimed.** Replaying a fixture
   under `Bytes(1)` does *not* produce an identical event stream: the engine emits a line
   item per advance, so a byte-at-a-time read produces many more `Appended` revisions than
   one whole read does. That is correct behavior, not a defect. What must be identical is
   the *substance* — the concatenated output text per command, the block structure, the
   exit codes, and whether markers were recognized at all. That is B2's cardinal property
   (text is never lost) plus B3's marker recognition, asserted across the whole fixture
   suite instead of one hand-authored case.

4. **Shells compose as decorators, and `Unmarked` is the first.**

   A shell that emits no markers is not a separate transcript; it is any shell with its
   markers removed. So the marker-less case is a decorator wrapping another shell and
   dropping every marker it produces, and `unmarked_session.json` is deleted in favour of
   `Unmarked::new(TranscriptShell::builtin())`.

   That is the composition the entry exists for: any transcript crossed with any
   far-end trait, instead of a fixture per combination. It is also the honest model of
   DESIGN's reliability case 2 — integration missing is something that happens *to* a
   working shell, not a different shell.

   One decorator ships, not a family. `Unmarked` has a consumer the moment it lands (B6's
   unintegrated path, and the manual matrix). Anything else would be a variant with no
   caller, which is the shape B1 refused to create.

5. **Not everything becomes a shell trait, and the test is who is misbehaving.**

   `forged_marker.json` and `no_end_marker.json` stay transcript **rules**. DESIGN's case
   3 is "a program printing OSC 133 itself" and its case 1 is a command that genuinely
   keeps running — both are things a *program* does, so they are properties of the command
   that was run, which is exactly what a rule describes. Case 2 is a property of the
   *shell*, which is why only that one becomes a decorator.

   Stated as a rule for later: if it is true of everything the far end will ever say, it is
   a shell; if it is true of one command, it is a rule.

6. **Placement: both live in `acter-transports`, not `acter-shells`.**

   `acter-transports/src/fake.rs` plus `fake/` holding the trait, the transcript-backed
   implementer, the decorator and the chunking strategy. `ScriptedTransport` shrinks to
   the composition of a `Box<dyn FakeShell>`, a `Chunking` and a `Clock`.

   `acter-shells` is deliberately left empty. Its stated theme is shell knowledge the
   domain *calls for* — injection snippets, quoting rules, completion strategy — behind
   the `ShellAdapter` port. A fake far end is not that: the domain never calls it, and it
   sits on the far side of the transport seam rather than beside it. Putting it in
   `acter-shells` would also make `acter-transports` depend on `acter-shells`, a new
   dependency between two adapter crates bought for nothing.

   This is the one judgment call in this spec that could reasonably go the other way, and
   it is recorded as such: the argument for `acter-shells` is the word "shell", and the
   argument against is every structural fact.

7. **This is not a `ShellAdapter`, and it does not become one here.**

   `ShellAdapter` is a driven port the domain calls for knowledge; it sits outside the
   byte path entirely. `FakeShell` produces bytes and is never called by the domain. The
   two are different enough that the composition only runs one way: a real shell adapter
   over a fake transport is realizable and useful, while a fake shell behind a real
   `LocalPty` is not, since ConPTY spawns an actual process.

   A fake shell may additively implement `ShellAdapter` at B5, once PowerShell exists to
   validate that trait's shape. Designing it here, against a fake alone, is how a port
   ends up fitting nothing real.

8. **`acter-core` is untouched, and so is every event the pipeline produces.**

   No port change, no protocol change, no binding regeneration, no frontend change. The
   `Transport` trait is unchanged and `ScriptedTransport` still implements exactly it.
   `pipeline.rs`'s assertions hold as written except where a deleted fixture forces a
   rewrite, which is the strongest available evidence that this is a refactor and not a
   behavior change.

## Deliverables

### `acter-transports`

- `fake.rs` + `fake/`:
  - `shell.rs` — the `FakeShell` trait, `Script`, `Delivery`, `Submission`.
  - `transcript_shell.rs` — `TranscriptShell`, the transcript-backed implementer: the
    prompt sequence, the echo, the line discipline, rule matching and the interrupt
    predicate, all moved out of `scripted.rs` and `transcript.rs` unchanged in behavior.
  - `unmarked.rs` — the `Unmarked` decorator (decision 4).
  - `chunking.rs` — `Chunking` and the cut (decision 3).
- `scripted.rs` — `ScriptedTransport` reduced to composition plus the emission task: the
  clock, the select loop that keeps an interrupt answerable mid-wait, the read channel,
  `written()` and `last_resize()`.
- `scripted/transcript.rs` — `Step`'s read-cutting role removed from its documentation;
  zero-delay steps that existed only to cut a read are merged in the built-in transcript.

### Fixtures

- **Deleted:** `split_marker.json` (decision 3), `unmarked_session.json` (decision 4).
- **Unchanged:** `alt_screen.json`, `captured_prompt.json`, `device_query.json`,
  `forged_marker.json`, `no_end_marker.json`, and the built-in transcript apart from the
  merge above.

## Tests

- **The whole fixture suite under `Chunking::Bytes(1)`**, asserting the substance
  identical to the same suite under `Whole`: concatenated output text per command, block
  structure, exit codes, and marker recognition. This is the headline test and the reason
  the entry exists — it replaces one hand-authored split with a dimension every fixture is
  run under.
- `TranscriptShell` unit tests for what moved: the prompt sequence, the echo with and
  without a line ending, line discipline over a partial write, a control byte accepted
  with no line ending, rule matching and the default rule.
- `Unmarked` over the built-in shell: no OSC 133 sequence reaches the pipe, the underlying
  text is otherwise unchanged, and the session still answers every rule.
- `Chunking` as a pure function: `Whole` is the identity, `Bytes(n)` never emits an empty
  read and never reorders or loses a byte.
- `pipeline.rs` — the unmarked-session test rebuilt on `Unmarked` rather than a fixture;
  every other assertion unchanged, which is the refactor's own proof.
- Nothing sleeps or reads the real clock, per B3.5 acceptance criterion 2.

## Acceptance criteria

1. `cargo test --workspace` green; `cargo clippy --workspace --all-targets` clean under
   `-D warnings`; `cargo fmt --check` clean.
2. `acter-core` is untouched: no port, protocol, binding or frontend change in this PR.
3. Every fixture passes under both `Whole` and `Bytes(1)`, with the substance assertions
   of decision 3 holding across both.
4. `ScriptedTransport` contains no rule matching, no prompt, no echo and no line
   discipline; `FakeShell` implementers contain no clock, no channel and no `async`.
5. Module role declared on the first line of each new module's `//!` comment; the
   visibility ladder holds; only what a container must name is re-exported.
6. `acter-shells` is still empty, and `acter-transports` gained no new crate dependency.
7. No accessibility checklist: nothing user-facing changes, and the app still runs the A3
   fake as its default backend until B6. Stated in the PR body rather than omitted.

## Out of scope

- **Wiring any of this into the app** — B6, unchanged. This entry ships a better-shaped
  fake; B6 is still the entry that makes it the default backend.
- **A null `ShellAdapter`, and profiles as a configuration surface** — B5 and
  post-convergence respectively, for the reasons in decision 7 and in B6's spec.
- **More shell decorators.** A slow-to-start shell, one with an unusual prompt, one that
  drops bytes — each is cheap once the pattern exists, and each waits for an entry that
  needs it.
- **Lossy or reordering pipes.** `Chunking` cuts; it never drops or reorders. A pipe that
  loses bytes is a different failure model, and inventing it before anything tests against
  it would be guessing at what a broken transport does.
- **Capturing real transcripts** — B5's, unchanged.
