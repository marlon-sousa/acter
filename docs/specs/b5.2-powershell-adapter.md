# B5.2 — the PowerShell adapter

Roadmap entry 23.2. Agreed in conversation 2026-08-23. Depends on 23.1, which supplies the
port.

**The first shell that can tell Acter a command ended, and with what.** cmd can mark its
prompt and its command line and nothing else (B4.5), so every session so far has ended its
blocks by inference and has never had an exit code. PowerShell can emit all four OSC 133
markers, which makes this the entry where `CommandFinished`, `Announcement::Failed` and the
whole verdict path stop being machinery built against fixtures and start describing a real
session.

## Decisions

### 1. Editions are values, not two adapters

`PowerShell::windows()` for Windows PowerShell 5.1 (`powershell.exe`, present on every
Windows machine) and `PowerShell::seven()` for PowerShell 7+ (`pwsh.exe`, installed
separately). One implementer, one snippet, one set of markers; what differs is the program
name and — measured, not assumed — possibly nothing else.

**Which of them exist on this machine is not this entry's question.** Discovery is I/O and
belongs to the port 23.3 introduces and the list B7 builds. This adapter answers "how do I
start this edition", and answers it for an edition that may not be installed, which is a
pure function and testable as one.

### 2. The injection is an argument, not an environment variable, and it writes nothing

`powershell.exe -NoLogo -NoExit -Command "<snippet>"`. The snippet defines the prompt
function and the marker hooks, then `-NoExit` leaves an interactive session behind it.

**Nothing is written to the user's machine**, which is the same stance cmd's `PROMPT`
injection took and it is deliberate: no profile edited, no file dropped in a temp
directory, nothing to clean up, and nothing left behind if Acter is killed. It also
sidesteps execution policy entirely — a `-Command` string is not a script file, so the
policy that blocks unsigned `.ps1` files does not apply. That last point is measured in a
locked-down state rather than reasoned about, because a shell that refuses to start on a
managed machine is exactly the failure this product cannot afford.

### 3. The four markers, and which of them are guesses until measured

The shape, following the mechanism VS Code's PowerShell integration uses:

- **A** (prompt start) and **B** (command-line start) ride inside the `prompt` function,
  the way they ride inside cmd's `PROMPT` string.
- **D** (command end, with the exit code) is emitted by the *next* `prompt` call, since
  PowerShell runs the prompt function after each command. The exit code is where care is
  needed: `$LASTEXITCODE` reports a native program's code, `$?` reports whether the last
  *PowerShell* command succeeded, and a failing cmdlet leaves `$LASTEXITCODE` untouched. The
  rule has to make both cases honest, and a wrong exit code is worse than none — it becomes
  an `Announcement::Failed` spoken about a command that succeeded.
- **C** (output start) cannot come from the prompt function, because it belongs after the
  user's line has been read. The candidate is a `PSConsoleHostReadLine` wrapper.

**All four are measured off a real pseudoconsole before any of this is written**, the way
B4.5 measured cmd's `PROMPT` byte for byte rather than trusting the documentation, and for
the same reason: what a shell claims to emit and what arrives through ConPTY have already
differed once in this project.

### 4. PSReadLine is the first real test of B6.1's rewritten-echo rule

PSReadLine redraws the command line as the user types, so what reaches the engine is a
rewrite of the whole row, prompt included — precisely the case B6.1 named as the one a real
PowerShell session would exercise first, where the rule strips the prompt and reports
`None` rather than guessing at a heading. This entry is where that is proven against a real
shell rather than against a constructed transcript. A regression here is silent and awful:
every block gets the wrong heading.

### 5. EOF arrives here

`SessionIntent::Eof`, one keybinding-table row, and one adapter method saying what byte or
key sequence this shell wants. B6 deferred it to whichever entry first had a port to hang
it on, and this is that entry. PowerShell wants Ctrl+Z followed by Enter; bash wants
`0x04`; the port is what lets those be different answers to the same intent.

### 6. Golden transcripts

The first real PowerShell session is recorded in B2's transcript format and committed as a
fixture, which is what the original B5 entry asked for: a captured real session becomes a
replayable fake session, so everything above the transport can be tested against real
PowerShell behaviour without PowerShell.

## Files touched

- `crates/acter-shells/src/powershell.rs` — the adapter, its snippet, and its editions.
- `crates/acter-shells/src/lib.rs` — facade and `adapter_for` recognising both programs.
- `crates/acter-core/src/entities/protocol_commands.rs` — `SessionIntent::Eof` and its
  binding.
- `crates/acter-core/src/ports/driven/shell_adapter.rs` — the EOF method.
- `crates/acter-transports/tests/real_session.rs` — the real-shell tests below.
- `crates/acter-transports/tests/fixtures/` — the recorded transcript.

## Definition of done

- [ ] The snippet is measured off a real pseudoconsole and the spec's marker table is
      replaced by what was actually observed, including the bytes for each marker.
- [ ] All four markers arrive in a real session; a real `ShellMarkers::Full` session opens
      and closes blocks by marker rather than by inference.
- [ ] A failing command produces the right exit code, and a failing *cmdlet* and a failing
      *native program* are both reported correctly — the case where `$LASTEXITCODE` and `$?`
      disagree is a test, not a note.
- [ ] Typing with PSReadLine active produces correct headings, and a rewritten line reports
      `None` rather than a guess.
- [ ] The session starts under a restrictive execution policy.
- [ ] EOF reaches a real PowerShell and ends the session.
- [ ] A golden transcript is recorded and replays through the scripted transport.
- [ ] Unit tests for the snippet's shape and for both editions' launches; the real-shell
      tests are `#[ignore]`d like every other test that spawns a process.
- [ ] `cargo fmt`, `cargo clippy --workspace --all-targets`, workspace tests clean.

**Accessibility checklist in the PR body**, because this is the first session a listener can
hear a verdict in: a failing command announces its exit code after its output, a successful
one says nothing about its code, and the block boundaries a listener navigates by are the
shell's own rather than inferred.
