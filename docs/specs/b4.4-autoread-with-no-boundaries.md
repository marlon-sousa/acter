# B4.4 — autoread in a session with no boundaries

Roadmap entry 22.4, absorbing 22.10. Agreed in conversation 2026-08-22.

Today a real shell session says **nothing at all**. Acter renders everything to the
buffer and speaks none of it, so a user who runs a command hears silence and must go and
review the buffer to learn what happened. That is this entry's whole reason to exist, and
it is what a listener notices first.

Three changes, in one PR because they are not separable in use: turning autoread on
without suppressing the echo means the user hears their own typing read back on every
command, and both of those interact with when a block opens.

## What this changes, in one sentence each

1. **Autoread is no longer suppressed in a session with no shell integration.** Text that
   genuinely arrived is read aloud, whatever labelled it.
2. **The shell's echo of a submitted line is no longer forwarded as output.** It becomes
   the block's heading instead, which is where B6.1 already put it for integrated
   sessions.
3. **A block opens when the far end echoes the line, not when the user presses Enter.**
   This is 22.10's fix: a submission nothing ever read produces no empty heading.

## Two DESIGN amendments, both riding in this PR

Per CLAUDE.md a **Decided** item changes in the PR that implements the change.

### Reliability case 2 — "no auto-read" is removed

DESIGN's Reliability model says an unintegrated session degrades to "patience
announcement, manual buffer review, **no auto-read**. Honest degradation instead of wrong
guesses."

The honest-degradation argument was written when the alternative was *guessing* — a
prompt matched by its shape, output attributed to a command by inference. Reading text
that genuinely arrived is not a guess. It is the same category as autoread everywhere
else, and it is exactly the distinction B4.1 turned on when `command stopped` was removed:
a claim about something Acter could not observe is a guess, and repeating text that was
received is evidence.

What stays true is the rest of case 2: no exit code, no verdict, and the patience
announcement still fires. Only the silence goes.

### Edit field ownership — "no evidence means no block" narrows to the echo

The 2026-08-22 amendment required two-part evidence: the far end echoed the line **and**
the prompt anchor reappeared. Implementation measurement showed the second part regresses
the commonest thing a user does.

Traced against a plain `cmd.exe` session with no nesting: at `C:\Users\marlo>` the user
submits `cd projects`; the new prompt is `C:\Users\marlo\projects>`; the anchor never
reappears, so by the rule the next `dir` is stdin and gets no block and no heading. That
happens on **every** `cd`, and it protects a `y`, which is occasional. The trade is the
wrong way round.

There is no third option that keeps both. Once a command goes quiet leaving a new row on
screen, "the shell's prompt is back" and "the program is asking a question" are
indistinguishable without markers — the anchor's *reappearance* is the only thing that
separates them, and a changed prompt has no reappearance to offer.

So the rule narrows to the echo half: **a block opens when the far end echoes the line.**
The anchor is deferred to 22.5/B5, where an integrated session makes it pay — until then
decision 10 already gives every submission a block, including inside a container, so the
anchor's unique payoff does not yet exist.

The echo half still carries what mattered:

- **A password is protected**, because a password never echoes. History is gated on the
  echo, so a line that never came back is never saved. (No code here: command history is
  not implemented yet, so this lands as a DESIGN statement A4 must honour.)
- **22.10's empty headings are gone**, because a submission nothing read is a submission
  nothing echoed.

What is knowingly given up until the anchor lands: a `y` at a `[y/N]` prompt echoes, so it
opens a block. That is exactly today's behaviour in an unintegrated session, so nothing
regresses — it is a fix deferred, not a defect introduced.

## The mechanic, measured rather than assumed

Driving `LocalPty` and `AlacrittyEngine` directly, below the service, inside a real
container:

- `LineId(0) Appended "C:\Users\marlo>"` — cmd's prompt.
- `LineId(0) Appended "docker run -it --rm alpine sh"` — the echo, on the **same LineId**.
- `LineId(1) Appended "/ #"` — the container's prompt, a new line.
- `LineId(1) Appended " ls"` — the echo, again on the prompt's LineId.
- `LineId(2)`, `LineId(3)` — `ls` output.
- `LineId(4) Appended "/ #"` — the prompt again, a new LineId.

Two properties this spec depends on, both visible above:

- **Appends carry the delta, not the whole row.** The echo arrives as its own append
  (`" ls"`), separable from the prompt that shares its line. So suppressing the echo does
  not suppress the prompt, and no new engine surface is needed.
- **The echo is the first thing to arrive after a submission.** Nothing precedes it, so a
  block that waits for it is not waiting behind output that would be lost.

The same shape holds for the backlog 22.10 found: after the interrupt, the row is
`C:\Users\marlo>` followed by an append of `echo acter-typeahead-1`, which is the pending
submission's text exactly.

## Design

### The echo does for an unintegrated session what `C` does for an integrated one

`Pump::submit` stops opening a block. Every submission is queued in `submitted`, which is
what an integrated session already does — the two branches of decision 10 collapse into
one.

A block then opens from the line stream:

- **A line's append matches a pending submission** (trimmed, exact, never fuzzy — B6.1's
  matcher): close whatever block is open, open a block for that submission with the echo
  as `command_line`, retire the submissions before it (B6.1 decision 3's rule, unchanged),
  and **do not forward that append as output**.
- **Any other line, with a block open**: forwarded to the open block, as today.
- **Any other line, with no block open**: open a block for the oldest pending submission
  with `command_line: None`, or mint a fresh id if none is pending, then forward.

That last case is the safety property and it is not optional: `SessionActor::output`
returns early when no command is active, so **output arriving with no open block is
silently dropped** — the product's cardinal defect. The rule guarantees a block exists
before any text is forwarded, so deferring the open can never lose text.

### Where the rule applies

Only where the tracker has not already delimited the echo: `region != Region::CommandLine`.

- **Unintegrated session** — every region is `Unstructured`, so the rule drives everything.
- **Integrated session, top-level shell** — the echo is in `CommandLine`, `wants` already
  rejects it and `Echo` already collects it for the heading. Unchanged.
- **Integrated session, inside a nested shell** — no `D` ever comes, so the container's
  echo lands in the open `C..D` region and `wants` accepts it. The rule applies, which is
  the case the roadmap says the matcher must cover on the forwarding path generally.

### Autoread

Delete the `integration != Integration::Unintegrated` condition in
`SessionActor::apply`'s `ReadMode::Auto` arm. Nothing else changes: the text was already
being taken and measured, so the size policy, the babble guard, the patience announcement
and `tooBigMessage` all behave identically. Only the `announce` call becomes reachable.

### The prompt is read aloud, deliberately

With autoread on, the span includes the prompt row. That is kept, agreed in conversation:
without a `D` the prompt reappearing is the only evidence a command finished, so reading
it is what makes a silent success audible — which is what 22.9 wants. The comfort question
for a decorated prompt stays 22.9's, and needs a real listen over many commands.

### What `grace_expired` stops doing

Its block-opening branch — adopting the most recent submission when the session is flagged
unintegrated — is removed. It existed so that "everything arriving from here on has
somewhere to go", and the no-open-block fallback above now guarantees that for every path
rather than for this one.

## Acceptance criteria

1. An unintegrated session reads its output aloud. The existing test asserting the
   opposite is inverted, not deleted, and says why.
2. A command's own echo is never forwarded as output, in an unintegrated session and
   inside a nested shell in an integrated one.
3. `CommandStarted` for an unintegrated session carries `command_line: Some(echo)`, so the
   frontend renders one heading rather than a heading plus a duplicate first line.
4. A submission the far end never echoes opens no block: no empty heading.
5. Output never reaches a session with no open block — asserted directly, since the actor
   drops it.
6. When a backlog is released at once, each released submission gets its own block with
   its own output, rather than two empty headings and one block holding everything (22.10).
7. Blocks still claim submissions in submission order, and B6.1's retiring rule still
   holds. Its existing tests pass unchanged.
8. The prompt row is forwarded and spoken.
