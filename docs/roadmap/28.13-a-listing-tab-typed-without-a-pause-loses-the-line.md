# 28.13 — After a listing Tab typed without a pause, the field holds the candidates.

Lane: keyboard-routing. Board: [../ROADMAP.md](../ROADMAP.md). This file is the entry until a spec absorbs it; the spec's PR deletes it.

Found on 2026-09-25 while measuring V2.5 (53.5), through the `SessionEvent`s of a real
`LocalPty` session at bash under WSL, set up, in far-end line mode.

- **Keys 30 ms apart, the same as `far_end_settle`.** `ls /etc/pa` was typed, then Tab, then Tab
  again 200 ms later. Bash listed `pam.conf  pam.d/    passwd    passwd-` and redrew the line on
  the row below. The listing reached the buffer, but the field was sent
  `pam.conf  pam.d/    passwd    passwd-` rather than `ls /etc/pa`.
- The anchor stayed on the row the line was first typed on. After Ctrl+U, `echo x` and Ctrl+L,
  the row the line had moved to was printed as a block with no heading,
  `marlon@splyt:/mnt/c/Users/marlo$ echo x`.
- The same happened in a session unit test: typing `ls`, settling, then ` /tmp/al` and Tab without
  settling, with the candidates and the redrawn line drawn below, left the field holding the
  candidates.
- 28.6 made the field follow a line redrawn below a listing, and its test passes: there the typing
  had settled before Tab. What differs here is that it had not.
