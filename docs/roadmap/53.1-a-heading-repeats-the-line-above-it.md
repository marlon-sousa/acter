# 53.1 — A heading repeats text that is already on the line above it.

Lane: lane-5-look. Board: [../ROADMAP.md](../ROADMAP.md). This file is the entry until a spec absorbs it; the spec's PR deletes it.

**A heading repeats text that is already on the line above it.** Spec: none yet → specify first.

Found on 2026-09-23 while testing V2 (PR #72) against real shells in far-end line mode, with the
V2 build driven over the embedded WebDriver. The buffer's structure was captured and a
screenshot taken at each step.

- **An answer to a program's question shows twice.** PowerShell `Read-Host 'Your name'`
  answered `Marlon`: a row `Your name: Marlon`, then a heading `Marlon`, then the output
  `Marlon`. The same happened with `$host.UI.PromptForChoice(...)` answered `n` (row ending
  `(default is "N"): n`, heading `n`); cmd `set /p NAME=Your name? ` (row `Your name? Marlon`,
  heading `Marlon`); Python `input('Python asks: ')` under cmd (row `Python asks: ok`, heading
  `ok`); and bash `read -p 'Name: '` under WSL (row `Name: Marlon`, heading `Marlon`). On
  screen, the heading is a second, brighter copy of the answer.
- **In bash under WSL, not set up, every command shows twice.** The row
  `marlon@splyt:/mnt/c/Users/marlo$ read -p 'Name: ' n; echo hi $n` is followed by the heading
  `read -p 'Name: ' n; echo hi $n`. The status bar read "connected to wsl, bash. You will hear
  what commands print here, but not whether they worked."

Spec 28 decision 7 makes these headings: at Enter, a non-empty anchored row opens a block
headed by its text. For a screen reader user they are how the buffer is navigated. For a
sighted person, the text is already on the row above.
