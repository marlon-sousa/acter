# 53.2 — A prompt the shell does not mark never shares a line with its command.

Lane: lane-5-look. Board: [../ROADMAP.md](../ROADMAP.md). This file is the entry until a spec absorbs it; the spec's PR deletes it.

**A prompt the shell does not mark never shares a line with its command.** Spec: none yet → specify first.

Found on 2026-09-23 while testing V2 (PR #72) against real shells over the embedded WebDriver.
V2 folds `p.prompt` paragraphs, which exist only when the session marks its prompts.

- **cmd:** the buffer held no `p.prompt` at all. Each prompt arrived as an output row,
  `C:\Users\marlo>`, followed by the command's heading, so on screen the prompt and the
  command sit on separate lines. In one case the heading itself began with the prompt:
  `C:\Users\marlo>python -c "input('Python asks: ')"`.
- **bash under WSL, not set up:** no `p.prompt` either. Prompt and command arrived together
  as one output row, which is entry 53.1's duplicate.

Against PowerShell every prompt was a `p.prompt`, and V2 folded all of them.
