# 53.5. The command line's own row is printed after the next prompt

Lane 5, the look.

Found on 2026-09-25 while measuring 53.4, through the `SessionEvent`s of a real `LocalPty`
session in far-end line mode.

- **Keys sent 30 ms apart, the same as `far_end_settle`, at Windows PowerShell 5.1.** After
  `echo before` finished and its prompt was drawn, a block with no command line opened and held
  `o before`, the tail of the row the line was typed on. It was read aloud as "o before". The
  same happened for `echo after` (` echo after`) and `2+2` (` 2+2`), with and without a Ctrl+C
  before them. With keys 80 ms apart, PowerShell and cmd never did it.
- **bash under WSL, integrated, Ctrl+C at an idle prompt, keys 80 ms apart.** Bash echoed `^C`,
  a block headed `^C` failed with 130 (entry 28.12), and after the prompt a block with no heading
  opened holding ` ^C`, from the row the prompt was on. It was read aloud as " ^C". In local
  mode, nothing reached the buffer.
- In both cases the stray block comes after the prompt, so in the buffer the prompt is followed
  by a block with no heading, as in 53.4.
